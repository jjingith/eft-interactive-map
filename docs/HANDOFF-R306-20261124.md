### 1.2 CMD 闪窗两处 ✅ 已改、其中浏览已实测

- **浏览闪窗（已修+已实测）**：`tools/serve.py` 的 `pick_folder_dialog()` 加了
  `CREATE_NO_WINDOW`。旧注释说「加了对话框会被隐藏」是**错的**——已用探针
  `build/_probe_pickfolder.py` 实测（EnumWindows 按 powershell PID 找 `#32770` 对话框）：
  无标志与 CREATE_NO_WINDOW 两种方式对话框都可见。探针文件保留着可重跑。
- **安装闪窗（已改、未端到端验证）**：`tools/installer.py` 的 `_run_legacy_uninstaller()`
  从 `CREATE_NO_WINDOW` 改为 `CREATE_NEW_CONSOLE + STARTUPINFO(SW_HIDE)`。
  原因：旧版（≤0.2.7）卸载器代码创建 `cmd /c` 时没加隐藏标志，GUI 父进程（无控制台）
  的控制台子进程会**新开可见控制台**=升级时闪黑窗；给它分配一个隐藏控制台让孙进程继承即可。
  现行代码（0.2.8.3 起）所有 spawn 其实都已带 CREATE_NO_WINDOW（逐处核对过，含
  `cmd.exe` 延迟删除、快捷方式 PowerShell），所以这个改动主要覆盖「从更老版本升级」的场景。
  建议接手后跑一次真实安装验证（见 §4 验证清单）。

## 3. 本轮已确认的关键事实（避免重查）

- **`CREATE_NO_WINDOW` 不影响 FolderBrowserDialog 显示**（探针实证）。serve.py 旧注释
  的说法是错的，注释已改。
- 安装器现行代码所有 spawn 都带 CREATE_NO_WINDOW；升级闪窗来自更老版本卸载器的
  无标志 `cmd /c`，用「隐藏控制台继承」方案规避（已改，待真机验证）。
- 情报物品板块 0 项是**数据真相**：92 个全是 noFlea 任务情报；可交易情报在交换物品板块。
- 前端板块 chip 的「N 项」来自 tarkov.dev handbookCategories 全量计数（服务端
  `_sector_summary` 的 `items` 字段），不是有行情的条数。
- 菜单绑定机制：`bindMenus()` 收集 `.app-menu`（排除含 `.app-app-panel` 的）；
  `bindAppMenu()` 专管 `#am-app`/`#am-app-panel`；通用面板无 `.app-menu-item` 时
  键盘只处理 Escape（对话框型面板的既定约定）。
- `#am-mini-panel` 会被 mini 模式（?mini=1）临时搬进小窗再原位放回
  （app.js miniMenuOpen/Close），所以它必须留在主 DOM，不能进 `display:none` 之外的
  特殊容器——放 `#app-legacy-sec` 这种 hidden 容器也要确认 mini 模式不受影响
  （hidden 面板被 miniMenuOpen 显式 `panel.hidden=false` 打开，实测过 R281 时代如此）。
- modern-flat.css 用 `html body button:not(...)` + `!important` 给所有 button 上扁平皮肤；
  作用域内改按钮样式必须同样带 `!important` 并用更高特异性（本轮 changes.css 有先例）。
- 新增 data 文件必须登记 `build/package_files.ps1` 的 `$RuntimeFiles` + `build.ps1`
  `$MustHave`（本轮无新增 data 文件）。
- Chrome headless `--screenshot` 在首屏渲染后立即抓图，`--timeout`/`--virtual-time-budget`
  都不可靠；交互验证用「MutationObserver 一渲染就点 + 把结果画到页面」的探针法。
