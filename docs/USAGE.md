## 它是什么 / 不是什么

| 是 | 不是 |
| --- | --- |
| 本地离线的互动地图：撤离点、转移点、出生点、物资、高级资源点、危险区、上锁的门、Boss 刷新点、BTR 停靠点、地名标注，含多楼层切换，可缩放平移、可搜索 | 不是游戏外挂：**不读内存、不注入进程、不做透视/自瞄** |
| 数据里没有的图不硬塞（收录上游有 SVG 底图的 10 张常用图，加上实验室 / 迷宫这两张只有瓦片的图，共 12 张） | 不做联机同步、不显示他人位置 |
| 底图与数据来自社区公开的 MIT / CC BY-NC-SA 许可资源，逐条署名 | 不含任何游戏资源文件，不爬虫、不上传任何用户数据 |

### 与游戏的关系

两条数据都来自游戏**自己写到磁盘上的文件**，默认全程不碰游戏进程：

- **实时定位**：监听截图目录、解析**截图文件名里的坐标与朝向**（社区公开做法）。
- **战局与任务**：跟随游戏目录下的 `Logs`，从日志文本里识别战局生命周期与任务事件，
  用来**进图自动切图**和统计本局任务（详见下文「日志监控」）。
- **自动截图（可选，默认关）**：在战局中按间隔向游戏窗口**模拟按下截图键**，
  让游戏自己往截图目录写图，实现「实时跟踪」；因为要模拟输入，需要游戏窗口在前台（详见下文「自动截图」）。

启动器会自动探测 `文档\Escape from Tarkov\Screenshots` 与常见盘符下的 EFT 安装目录，找到就填上；
探测不到可以在小窗里手填或点「浏览…」选。

## 界面用法（逐项详解）

网页框架是 **Windows XP（Luna）风格**的浅色窗体（菜单栏 + 左侧栏 + 地图区），地图区与上面的标记保持深色，
方便看清底图与彩色标注；小图标与地图标记沿用原来的样式，没有变。

- **顶部菜单栏「战局与任务」**：战局阶段、任务计数、自动截图 / 自动删除状态都收在这里，点开才展开；
  点面板以外的地方或按 `Esc` 收起。平时不占侧栏空间。
- **地图**：左侧点选切换；上次看的地图会被记住（`localStorage`）。
- **平移/缩放**：按住左键拖动平移；滚轮缩放（0.5×–20×）；右上角「复位」回到整图适配。
  缩放走的是 SVG `viewBox`，每次都是矢量重绘，**放大不会变糊**。
- **自动居中**：右上角按钮显示「自动居中／已锁定」。自动居中时实时定位一变就把地图平移到该点；
  一旦你拖动地图就切到「已锁定」按手动视角，点一下即可恢复。（原「跟随」改名而来，行为一致。）
- **定位自动缩放**：启动器里勾上后，拿到实时位置时按**最近一次手动缩放比例**（首次 4×）自动缩放到合适大小，顺带居中。
- **自动截图**：启动器里可开总开关（**默认关**），并设「间隔（ms）」与「按键」（可从日志同步）。
  开启后，只要**在战局中且游戏窗口在前台**，就会按间隔模拟按下截图键，让游戏自己写图——
  这样实时定位的坐标就会持续更新（见下文「自动截图（可选）」）。
- **自动删除截图**：紧挨着自动截图的另一个开关（**默认关**）。开启后，读出位置就把多余的老截图删掉，
  只保留最新 1 张供定位（见下文「自动删除截图（可选）」）。
- **声音提示**：启动器里可开总开关，下挂三个子开关（战局开始 / 开始加载战局 / 开始匹配），
  每个都能「选取音频…」换成自己的音频文件（选择后自动拷进配置目录的 `sounds/`，换机不丢）；
  不选就用内置提示音。浏览器要求先有一次点击或按键才允许出声，页面任意处点一下即可解锁。
- **图例 / 图层**：左侧分 6 组——**撤离点 / 转移点**（共用 / PMC / Scav 撤离点 + 转移点，4 项合在一组）、物资（**高级资源点**——一个总开关 + 按物品拆的 7 个子开关，见下——加上 **容器按类别拆 14 个开关**，见下表，外加散落物资）、
  出生点（玩家 / Scav / AI PMC / 狙击手 / Boss 刷新点）、钥匙与门（上锁的门 / 汽车后备箱）、危险区域（雷区 / 炮击区）、
  其他（固定武器 / BTR 停靠点 / 地名标注）。命名与分组对齐参考站，**每行右侧显示该标记在当前地图上的数量**；
  关掉的图层整行压暗，状态会被记住——既存在浏览器本地（`localStorage`），也**写回配置文件**
  （`config.json` 的 `ui` 块），所以换浏览器打开还是同一套勾选。
  **物资 14 类默认开启**（打开地图就能看到物资点）；**高级资源点默认只开「比特币 / 私酒 / 钥匙卡类」这三个最值钱的子类**
  （钥匙类有 48 种物品、点位最密，默认关掉免得糊成一片）；其余开关里只有撤离点、转移点、危险区、Boss、地名、固定武器默认开。
  地图上的物资点画成**贴近实物的小图标**（保险箱有转盘、工具箱有提手、尸体是骷髅…），图例每类前面用的是同一套小图标；
  撤离点 / 转移点画成**彩色盾牌 + 奔跑小人、下面带名字**（照参考站款式，按阵营配色：PMC 绿 / Scav 黄 / 合作（共用）蓝 / 转移红）；
  出生点、Boss、狙击手、上锁的门、BTR、高级资源点同样是**小图标**（形状照参考站款式）——
  出生点是三角标（玩家绿 / AI PMC 蓝 / AI Scav 橙）、狙击手是圆环内带 X 的准星、Boss 是骷髅头、
  上锁的门 / 后备箱是黄色挂锁、BTR 停靠点是红色八边形、**高级资源点按物品给各自对应的图标**
  （BTC 金币 / 各色钥匙卡 / 钥匙 / 私酒瓶 / 除颤器，判定见 `app.js` 的 `VALUABLE_ICON_RULES` + `KEY_ICONS`）；
  其中**物资容器、比特币、LEDX、私酒、除颤器、六色实验室钥匙卡 + 黑卡、Object 两张卡、蓝色文件夹材料，
  以及 190 把具体钥匙（含公寓管理员 / Knossos LLC 这类固定刷新钥匙）**用的是**本地图片素材**
  （`assets/icons/` 下 64×64 透明 PNG，共 217 个，由 `tools/iconize.py` 从用户提供的 wiki 截图逐行抠图导出），
  **只剩手提箱 / 收银机 / 其他容器与高级资源点的「兜底宝石」仍是手画的 SVG**——
  前端在 `app.js` 的 `ICON_PNG` 表里按 key 命中素材就贴图、未命中退回手画：具体物品名先走 `KEY_ICONS` 精确查表，
  认不出再退回 `VALUABLE_ICON_RULES` 正则，两套图标在缩放时都保持屏幕大小恒定；
  点开任意标记（出生点 / 撤离点 / 转移点 / Boss / 物资点…）时，会在**该标记旁边弹一个小浮窗**显示简略信息（名称、类型等），
  同时左侧「标记详情」仍给出完整信息（名称、类型、阵营、世界坐标；容器另含类别、高级资源点另列「可能刷出」哪些物品）；
  雷区 / 炮击区这类有轮廓的画成多边形，只有坐标的退化成点。
- **高级资源点**：只在固定刷点上**有概率**刷出的高价值物品——实体比特币、私酒、LEDX 皮肤透照仪、便携式除颤器、
  各色实验室钥匙卡与 Object #21WS / #11SR 钥匙卡、TerraGroup「蓝色文件夹」材料，以及**在地图上有固定刷新点的钥匙**
  （如公寓管理员钥匙、Knossos LLC 设施钥匙——这类刷点的物品池里只有它自己）。它和「散落物资」是同一批地面刷点，
  构建期按物品池筛出高价值的那部分单独成层（判定名单见 `tools/fetch_data.py` 的 `HIGH_VALUE_ITEMS`）；
  点开可看该点**可能刷出**哪些物品。各图数量：灯塔 223、街区 229、森林 109、立交桥 99、海岸线 114、海关 68、储备站 40、工厂 3、码头 3、中心区 0（合计 888）。
  **图例里它是「一个总开关 + 7 个子类」**：总开关「高级资源点（全部）」一键全开 / 全关（只开了一部分子类时显示半勾），
  下面缩进列出 **比特币 / 私酒 / 钥匙卡类 / 钥匙类 / LEDX / 除颤器 / 其他高价值** 七类，各自独立开关、各自显示点数
  （「其他高价值」= 蓝色文件夹这类既不属钥匙也不属钥匙卡的物品）。一个刷点可能同时属于多类
  （例如同一点既可能刷 BTC 也可能刷除颤器），显示时按「已开启子类的并集」算，**同一点不会重复画两层图标**。
  搜索结果定位到某个高资点时会自动打开它所属的那个子类开关。
- **上锁的门看钥匙**：点地图上的上锁的门 / 汽车后备箱，除了左侧「标记详情」会出现「需要钥匙：……」，
  还会在**图例对应那一行旁边弹一个小浮窗**写出要哪把钥匙（钥匙名在构建期由物品 id 解析成中文，见 §数据来源）；
  这行「需要钥匙」在浮窗与「标记详情」里都会**贴出该钥匙的图标**（有专属图标就贴专属图，没有则退回通用钥匙图）；
  需要通电的门另外标一行提示。浮窗 8 秒后自动收起，换图或点别处也会收起。
- **楼层**：多层图会在左侧列出楼层（由下到上），点一下就只看那一层，点「全部」全显——
  **只选一层时，比它低的楼层会以半透明垫在下面**（好看清当前楼层压在什么位置上），比它高的仍然隐藏。
  底图里跨层共用的部分（楼梯等）始终可见，不会因为切层而消失。
  勾选「跟随截图自动切层」后，实时定位的高度 `y` 会落进上游的高度波段并自动切到对应楼层。
  海岸线的「一层」指度假村一层（上游数据没给它高度区间，本项目在构建期按度假村轮廓补了一条一层波段），
  切到「一层」即可看到该层的房间门（含上锁的门）与一层物资。
- **搜索**：输入名称子串，结果**按「类型」聚合成条目**——搜「物资埋藏桶」只会出现「物资埋藏桶」这**一条**
  （不会再混进其它容器）；搜「比特币」「私酒」这类**高级资源点物品名**也能搜到（高资点一条刷点可能列多种物品，
  按**物品名**拆成多条）。可搜撤离点 / 转移点 / 物资容器 / 高级资源点 / 上锁的门 / Boss / BTR / 固定武器 / 地名；
  每条右侧写明「类型 · 子类 · N 处」（N 是**当前地图**上的点数），排序按「完全相同 > 前缀 > 包含、其次点数多的在前」，最多 30 条。
  点条目本体：先切到它所在楼层，再居中并高亮脉冲环，同时弹出「标记详情」
  （名称、类型、阵营、世界坐标含高度 `y`、所在楼层、危险类型、刷新概率等）。
  每条还带两个动作按钮：**「钉选」**与**「路线」**（见下）。
- **钉选**：搜索结果里点「钉选」，**该类型在地图上的所有图标都加一圈黄色高亮描边**（按钮变「已钉」，再点取消）。
  钉选与图层开关一样持久：既存浏览器本地（`localStorage`），也写回配置文件 `ui.pins`，换浏览器打开还在；最多记 300 条。
- **导航路线**：在搜索结果或「标记详情」的「加入路线」把点加进途经点；顶部菜单「导航与路线」里可查看、清空、反转，
  还能勾「从实时定位出发」把当前玩家位置当起点。地图上按途经点的世界坐标**直线连成折线并标序号**，
  面板给出点数与**直线距离**合计（最多 60 个点）。注意：本工具没有导航网格（NavMesh），折线是直线、跨楼层会「穿墙」，仅供方向参考。
- **状态条**：显示当前地图、光标处的游戏世界坐标、实时定位状态（青色表示已定位到玩家，并提示是否可能不在当前地图）。

## 实时定位（已实现）

`serve.py` 后台线程轮询 EFT 截图目录（默认 `文档\Escape from Tarkov\Screenshots`，
可用 `--screenshots` 覆盖），解析截图文件名里的坐标与朝向，经 **SSE**（`GET /events`）推给页面，
页面上以青色光点 + 朝向箭头显示玩家位置，支持自动居中（跟随）与手动锁定。

- 截图目录不存在时**自动停用实时定位**，地图其余功能照常；启动框自检那一步会写明「实时定位未开启」。
- 文件名解析不出来时**忽略该文件、不误报**，状态条显示原因（如「截图目录里还没有可解析的截图」）。
- 只有位置**真的变了**才广播，另有 15 秒心跳注释保持连接。
- 定位点与地图标注共用同一套坐标换算，因此天然对齐；朝向也要过同一套变换才是屏幕上的正确方向。
- 截图里的高度 `y` 会被换算成楼层：命中上游的高度波段就自动切到那层（可在左侧关掉「跟随截图自动切层」）；
  该高度没有对应的矢量底图时只提示、不切层。
- 相关接口：`GET /api/health`（含 `position` / `positionAvailable`）、`GET /api/position`（当前快照）、`GET /events`（SSE）。

文件名格式与四元数约定由**真实样本**（本机 6588 张截图）反推确定，见 `tests/test_screenshot_parse.py`。

> 光凭坐标**无法**反推你在哪张图：上游数据里不同地图的坐标范围大量重叠（6493 个采样点中位命中 8 张图）。
> 所以「哪张图」由日志来定（见下节），坐标只负责在图内定位。

## 日志监控（已实现）

`serve.py` 另起一个后台线程跟随**游戏目录下 `Logs` 里最新的会话文件夹**，从日志文本里识别战局生命周期
与任务事件，经 SSE 推给页面。实现细节在 `tools/eftlog.py`，配置项在 `tools/config.py`。

### 日志长什么样

```
Logs\log_2026.10.17_19-42-17_1.2.5.0.48146\      ← 会话目录（带 log_ 前缀）
        2026.10.17_19-42-17_1.2.5.0.48146 application_000.log   ← 文件名**不带**前缀
        2026.10.17_19-42-17_1.2.5.0.48146 backend_000.log
        2026.10.17_19-42-17_1.2.5.0.48146 push-notifications_000.log
        2026.10.17_19-42-17_1.2.5.0.48146 errors_000.log
```

四个通道各管一摊，按**行文本**匹配（不是解析二进制、不挂钩子）：

| 通道 | 关键行 | 产出事件 |
| --- | --- | --- |
| `application` | `MatchingCompleted` | `matching` 开始匹配 |
| `application` | `scene preset path:maps/<id>_preset.bundle` | `map` 识别到地图（`Bigmap` = 海关） |
| `application` | `LocationLoaded` | `loading` 开始加载战局 |
| `application` | `[Transit] ... RaidId:<hex>` | 本局战局 id |
| `application` | `PlayerSpawnEvent` | `start` 战局开始 / 出生 |
| `backend` | `client/quest/list`、`client/match/local/end` 等 | 参考信息 |
| `push-notifications` | `{"type":"new_message", ... "templateId":"<任务 id> description"}` | 任务接取 |
| `push-notifications` | 同上，后缀 `successMessageText` + `items.data` | 任务完成（带奖励件数） |
| `errors` | `Quest with id <id> wasn't found!` | 任务失败 |

进去一次战局的完整序列是：`matching → map → loading → start → end`。地图 id 与战局 id 分别在**不同的行**
出现，所以快照里要把前文串起来记（`merge_raid`），否则页面中途打开就只剩最后一条、无法自动切图。

### 页面上能看到什么

顶部菜单栏的「**战局与任务**」面板：当前阶段（开始匹配 / 识别到地图 / 开始加载 / 战局开始 / 战局结束）、
识别到的地图、本局 `RaidId`、当前会话名；下面「本局完成 / 本局接取」计数与事件流
（时间、接取 / 完成 / 失败、任务 id、完成时的奖励件数）。

**进图自动切图**：日志识别出地图后自动切到底图（`bigmap → 海关`、`sandbox_high → 中心区`、
`tarkovstreets → 街区`、`factory4_day/night → 工厂`、`shopping_mall → 立交桥`、`rezervbase → 储备站` 等）。
已在该图不会重复切换，避免把你正在看的视角重置掉；本工具没收录的图只在面板上写一行提示、不硬切。

### 任务进度的日志局限（**如实说明**）

日志只给得出**任务的推送通知**，所以：

- 只统计**本局**：任务接取 / 完成 / 失败，计数在本局开始时（新一轮匹配或出生）归零；
- **没有条件级进度**（「击杀 5 个 Scav / 已 3 个」这类拿不到），只有整条任务的开始 / 完成 / 失败；
- 事件里只有**任务 id**，拿不到任务中文名与描述（日志没有这张表，页面只显示 id）；
- **不做跨会话累计**：重启或换局不保留历史已完成清单（要累计得另存一份状态，目前刻意不做）。

### 配置项

存在 `%APPDATA%\EFTMap\eftmap.config.json`；启动器与页面共同维护。
启动器负责写 `game_dir` 到 `sound` 这些项；页面的界面偏好写进末尾的 `ui` 块。
配置**不再放在软件目录**——旧的软件目录配置与 `sounds/` 会在首次启动时自动迁移过来（原文件保留不删）。

| 键 | 含义 | 默认 |
| --- | --- | --- |
| `game_dir` | 游戏目录（内含 `Logs`）；留空则自动定位 | 自动 |
| `screenshots_dir` | 截图目录（实时定位用）；留空则自动定位 | 自动 |
| `auto_zoom` | 定位自动缩放（沿用最近一次手动比例，首次 4×） | 关 |
| `auto_center` | 点位自动居中 | 开 |
| `auto_start` | 开窗即自动启动 WebUI | 关 |
| `auto_screenshot.enabled` | 自动截图总开关 | 关 |
| `auto_screenshot.interval_ms` | 自动截图间隔（毫秒，钳在 200–60000） | 1000 |
| `auto_screenshot.key` | 截图按键名（空 = 用日志同步到的游戏内截图键） | 空 |
| `auto_delete.enabled` | 读出位置后自动删除截图的开关 | 关 |
| `auto_delete.since` | 时间闸：只删这个时刻**之后**产生的截图（由开关「关→开」时自动写入） | 空 |
| `sound.enabled` | 声音提示总开关 | 关 |
| `sound.<key>.on` / `.file` | 三个提示音（`raid_start` / `location_loading` / `matching`）各自的开关与自定义文件 | 开 / 内置 |
| `ui.layers` | 页面上图层开关的勾选状态（key → 是否显示），由页面「勾选即保存」 | 空（用页面默认） |
| `ui.floor_auto` / `ui.floor_filter` | 页面上的「跟随截图自动切层 / 按楼层过滤标记」两个开关 | 空（用默认：都开） |

目录自动定位顺序：命令行参数 → 配置文件 → 自动探测（环境变量 `EFT_GAME_DIR`、常见盘符下的 `EFT` /
`Escape from Tarkov`、常见安装路径）。**都找不到就留空**，可以在小窗里手填或「浏览…」选。

### 相关接口

`GET /api/logstate`（当前跟随状态 + 累积的战局 / 任务快照 + `shot` 自动截图状态 + `clean` 自动删除状态）、
`GET /api/config`（运行期配置）、`POST /api/prefs`（页面把界面偏好写回配置：`{"ui": {...}}` 或 `{"auto_center": bool}`，
同时给所有打开的页面广播一次 `config` 事件）、`GET /sounds/<file>`（自定义提示音）、
`GET /events`（SSE：位置为无名帧，另加 `config` / `state` / `raid` / `quest` / `shot` / `clean` 命名事件）。

> 只**读日志文件**，不注入进程、不改游戏文件；日志轮转或换会话时会自动重新接入最新会话。

## 自动截图（可选，默认关闭）

实时定位靠的是**截图文件名**，所以截图越密、位置越新。开启自动截图后，`serve.py` 会另起一个线程
（`AutoShotter`，见 `tools/serve.py`），在**三个条件同时满足**时按间隔向游戏窗口发送一次截图键：

1. 启动器里勾了「启用自动截图」；
2. 日志显示**在战局中**（阶段为 `start`，来自上面的日志监控）；
3. **游戏窗口在前台**（模拟按键只能打到前台窗口；实现会先查前台窗口进程名是否为 `EscapeFromTarkov.exe`）。

发送用的是 Windows `SendInput` 注入**按下 + 抬起**（走扫描码，见 `tools/keyinput.py`），
按的是**游戏自己的截图键**——所以你可以在游戏设置里随便改键，本工具跟着走。

### 截图键从日志自动同步

**可以同步。** 游戏启动时会把**整套控制绑定**打成一个 JSON 写进会话日志（`application_000.log` 或
`output_000.log` 的**开头几行**），里面就有 `keyName: "MakeScreenshot"` 这一项：

```json
{"keyName":"MakeScreenshot","variants":[{"keyCode":["V"]},{"keyCode":[]}],"pressType":"Press"}
```

小窗里的「**从日志同步**」按钮就是读这一段（只扫文件头 ~8 MiB，不读整份日志），
把 `variants[0].keyCode[0]` 填到按键框里（实测本机 4 个会话都是 `V`）。`auto_screenshot.key` 留空时，
运行期也会自动回落到这个同步值，所以一般**不用手填**。

### 请务必了解这几点

- **反作弊**：EFT 带 **BattlEye**。模拟输入属于「向游戏发送输入」，**可能被反作弊判定为异常行为**。
  本功能默认关闭，是否需要请在了解风险后自行决定；本工具不读内存、不注入进程、不改游戏文件，
  但**不保证**不会被误判。
- **截图目录会持续增长**：间隔越短增长越快（本机截图目录已有几千张）。间隔被钳在
  **200–60000 ms**，请按需要设置，并定期清理 `文档\Escape from Tarkov\Screenshots`；
  或者开启下面的「**自动删除截图**」，让工具在读出位置后自己清掉。

### 前台窗口限制

游戏不在前台（切出到浏览器、看攻略等）时不会发键，这是刻意的——否则按键会打到别的窗口上。
所以本工具更适合「游戏全屏、地图放副屏/手机上看」的用法。

### 按键发送失败

被系统或安全软件拦截时会记下原因（面板与 `/api/health`、`/api/logstate` 里的
`shot.reason` 能看到），不会反复硬发。

顶部「战局与任务」菜单里会显示一行「自动截图：每 1000 ms 发送 V · 已发送 N 张」，
没在拍时会附上原因（未开启 / 不在战局中 / 游戏窗口不在前台 / 未取得按键）。

## 自动删除截图（可选，默认关闭）

开启自动截图后截图会越攒越多，这个开关让工具**在读出位置之后把多余的截图删掉**，
免得手动去清 `Screenshots`。它在启动器的「自动截图」分组里，**默认关闭**。

实现是 `ScreenshotPruner`（`tools/serve.py`），挑选逻辑在 `tools/screenshot.py` 的
`select_deletable` / `prune`。三条安全规则：

1. **只删「能解析出位置」的截图**。读不出位置的文件（比如手动在菜单里拍的图）一律不碰。
2. **保留最新 1 张**。实时定位就靠最新一张截图的位置，把它删了定位会直接断掉
   （`latest_position` 返回 None → 页面上位置消失）。所以**这是功能正确性的必要条件**，不是保守设置。
3. **时间闸**：只删「开关**由关变开的那一刻之后**产生」的截图（按文件 mtime）。
   第一次开启时工具会先把当前时刻写进 `auto_delete.since`，**这一轮一张都不删**，
   之后只清理这个时刻之后的文件。这样历史截图（本机 6656 张）与开关关闭期间攒下的图都不会被误删。

删除是不可恢复的操作；删不掉（文件被占用等）会静默跳过，下一轮再试。

顶部「战局与任务」菜单里会显示一行「自动删除截图：已删除 N 张（保留最新 N 张供定位）」，
未开启时显示「未开启（在启动器里开启）」。

## 已知限制

- **灯塔**、**森林**、**迷宫**是单层图，不显示楼层列表；其余 9 张图为多层图。
- **码头**在上游数据里没有撤离点与地名，只有出生点（默认关闭）、散落物资、危险区、上锁与 Boss 刷新点。
- 多层图默认只显示**主楼层**（如工厂为 `Ground_Floor`），避免叠影；其余楼层在左侧点一下即可看。
  楼层归属由上游的高度波段（`y` 区间 + 可选的 `x/z` 矩形）推出，命中不了就按主楼层算。
- 上游少数 Boss 刷新点的高度落在没有矢量底图的结构里（例如码头 `y ≈ -60` 的地下部分），
  此时按主楼层显示，**不丢点**。
- 上游有**少量标注落在底图矩形之外**（例如中心区属于 21+ 扩展区的撤离点、工厂东侧部分出生点）。
  这些点**照实保留、不静默丢弃**，视图会按标注包围盒外扩最多 12% 来容纳它们，越界过多的点会被裁掉。
- **实验室（The Lab）与迷宫（The Labyrinth）没有矢量底图**：上游 tarkov.dev 对这两张图只给**瓦片**（`tilePath` 走 `labs_v4/*`、`labyrinth/main/*`），配置里没有 `svgPath` / `svgBounds`。
  社区 SVG 仓库里的 `Labs.svg` 实测**与上游 `bounds` 对不齐**（绘制内容宽高比约 1.237，而 `bounds` 对应的世界矩形是 1.372，相差约 10%，标记会肉眼可见地错位），`Labyrinth.svg` 则根本没有。
  所以本项目改用**构建期拼图**：`tools/fetch_data.py` 按上游自带的 `transform` / `bounds` 算出每格瓦片在像素网格里的位置，
  生成一个合成 SVG（`assets/maps/TheLab.svg` / `TheLabyrinth.svg`，每层一个顶层 `<g>`，组内是 `<image>` 引用 `assets/maps/tiles/…` 下的 PNG），
  **坐标完全走上游自带的那套参数**，因此标记与底图严丝合缝。前端**一行都没有改**：它照旧读 SVG 的 viewBox 与顶层组来切层、缩放、垫半透明。
  - 瓦片取 **zoom 3**（实验室三层 + 迷宫合计 120 张、约 6.2 MB）；zoom 4 会到约 23 MB 而屏幕上看不出区别。
  - 实验室三层：一层（主层）/ 二层 / 技术层，图层名由构建期补上（上游这些层只有 `name`、没有 `svgLayer`，不补的话楼层功能整个不工作）。
  - 上游对没有内容的瓦片也返回一张 102 字节的全透明小图，构建期按字节数判定并跳过，所以合成 SVG 里只有真正有内容的格子。
  - 破冰船（Boreas）等其余瓦片图仍**不收录**：上游对它们连瓦片底图都没提供（同上，宁可不放，不做半成品）。
- 街区危险区里 `x -71.9 / z 0.6 / y 8.5`（狙击手区）的位置经核对**与上游数据逐字段一致**（`position` 与多边形顶点质心都落在该点），
  但按游戏内实测该处不应有狙击危险区 → **属上游数据问题**，本项目**照实保留、不擅自改**。
  需要修正的话，可在构建期加一张人工修正表（按「图 + 坐标」覆盖上游值），改法同 `FLOOR_BAND_EXTRA`。

> 另有若干功能层面的诚实限制，已如实写在各功能小节里：任务进度只统计本局、无视条件级进度、不跨会话累计（见「日志监控」）；
> 光凭坐标无法反推在哪张图（见「实时定位」）；自动截图的 BattlEye 误判风险与截图目录持续增长（见「自动截图」）。
