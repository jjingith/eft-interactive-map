# R17-B：全口径弹药列表问题排查

## 1. 排查过程（真实浏览器 + 数据不变量）

按任务书 B2 的数据链逐层核查，用 CDP 驱动真实 Chrome（155 headless）在
`http://127.0.0.1:8791/` 上做了 8 次换枪 + 1 次口径筛选，每一步都导出
弹药下拉的 option value → 回查 `data/ammo.json` 的口径：

| 步骤 | 选中枪械 | 下拉 option 数 | 实际口径 |
|---|---|---|---|
| 初始 | M4A1（800rpm） | 11 | 5.56x45 |
| 换 AKS-74N | 5.45x39 突击步枪 | 13 | **5.45x39** |
| 换 AKM | 7.62x39 | 9 | **7.62x39** |
| 换 MP5K | 9x19 冲锋枪 | 9 | **9x19** |
| 换 MP-133 | 12 铅径泵动 | 17 | **12g** |
| 换 Saiga-12K | 12 铅径自动 | 17 | **12g** |
| 口径筛选 5.45 | — | 同上正确 | — |

结论：**在干净会话（新开浏览器、最新 app.js）中未能复现「永远 5.56」**。

## 2. 数据面不变量（同样通过）

- 163 把枪的白名单共 **30 套不同的弹药集合**（不是一份列表复制 163 次）；
- 逐条核对：所有 `allowedAmmo` 的口径与枪械口径一致，唯一例外是 **PP-9 楔子（9x18PMM 枪可以吃 9x18 PM 弹，14 条）**——这是上游数据的真实兼容关系，不是错误，保留；
- 六个代表口径（5.56 / 5.45 / 7.62x39 / 9x19 / 12g / 7.62x51）的白名单全部口径纯净。

## 3. 最可能的根因（用户环境的陈旧 JS）

R16 开发窗口内 `app.js` 有多个中间版本：`renderSimAmmoOptions` 与
`amSimOnGunChanged`（换枪 → 重渲染弹药/弹匣）是在交付前很晚才接线的。
如果浏览器标签页是在中间版本加载的（serve.py 对静态文件已发 `Cache-Control: no-store`，
但**已经打开的页面不会自己更新 JS**），就会出现精确的症状：

> 枪械下拉换什么，弹药下拉都停在首次渲染的 M4A1 列表（恰好全是 5.56）。

R16 交付后 `data/gun-compat.json` 等文件再未变过，`loadJSON` 也带 `cache: "no-cache"`，
数据面不会陈旧；唯一能陈旧的就是**打开中的标签页里的旧 JS**。

## 4. 本轮加固（让这类问题可自愈、可识别）

| # | 措施 | 文件 |
|---|---|---|
| 1 | **可见构建标记**：模拟器顶部操作条显示 `R17 构建 · compat <日期>`，用户一眼可核对浏览器里跑的是哪一版 | `app.js` `AM_BUILD` / `compatBuildStamp()` |
| 2 | 弹药数据晚到补渲染：`renderAmmoSim()` 挂 `ensureAmmo().then(重渲染弹药/弹匣/预设)`，先开模拟页不再出现空列表 | `app.js` |
| 3 | 弹药下拉带 `dataset.gun` / `dataset.cal` 标记，排查时一眼可见列表归属 | `app.js` |
| 4 | `state.ammo` 未加载时显示「正在加载弹药数据…」（disabled），不再静默给空列表 | `app.js` |
| 5 | 预设行的不兼容弹药在换枪时立即清空并提示（不只等装填时报错） | `app.js` `amSimOnGunChanged()` |
| 6 | 引擎侧 `constraints` 硬校验保持不变：即使 UI 出错，非法弹药/弹匣也进不了引擎 | `combat_sim.js` |

## 5. 给用户的核对方法

1. 强制刷新页面（Ctrl+F5）或关掉旧标签重开；
2. 看模拟器左上角是否显示 **「R17 构建 · compat <日期>」**；
3. 换枪后按 F12 检查弹药下拉元素：`data-cal` 应等于当前枪械口径。

## 5. R17S：缓存根因确认 + 版本参数修复

### 5.1 根因（用户「永远 5.56」复现链）

- `tools/serve.py` 本身已发送 `Cache-Control: no-store`（705 行起）；
- 但**已打开的 Chrome 会话**对同一 profile 内先前加载的 `app.js` 走 memory cache
  （`transferSize=0`、decodedBodySize=旧版本字节）——no-store 挡不住已驻留的内存副本；
- 用户标签页由此长期运行旧构建：旧版只有 5.56 白名单逻辑 → 任何枪都显示 5.56 弹药。

### 5.2 修复（不依赖人工刷新）

- `index.html`：`combat_sim.js?v=r17s2`、`app.js?v=r17s2`、`style.css?v=r17s2`；
  今后改这三个文件时同步升 `?v=` 与 `app.js` 内 `AM_BUILD`（同为 r17s2）；
- 模拟器顶部执行条常驻显示「R17S2 构建 · gun-compat 构建戳」，肉眼可核对版本。

### 5.3 修复后复测（同一无头 Chrome，重新导航即生效）

| 口径 | 枪械 | 弹窗弹药数 | 口径集合 | magCount |
|---|---|---|---|---|
| 5.56x45 | M4A1 | 11 | {5.56x45} | 24 |
| 5.45x39 | AKS-74N | 13 | {5.45x39} | 13 |
| 7.62x39 | AKM | 9 | {7.62x39} | 17 |
| 7.62x51 | 雷明顿 Model 700 | 8 | {7.62x51} | 9 |
| 9x19 | MP5 | 9 | {9x19} | 3 |
| 12g | MP-133 | 17 | {12g} | 7 |

- 六口径弹窗列表口径集合均为单值且与枪械一致；穿透力全部数值升序；
- 数据级不变量（163 枪）：弹药白名单为空 0；有弹匣槽但弹匣表为空 0；
  4 把固定弹仓/弹链枪正确标注「无独立弹匣槽」，不走弹匣逻辑；
- **结论：磁盘数据与代码本身无口径错误**；用户如再遇到「永远 5.56」，
  先核对页面构建标记是否为 R17S2（不是 → 强制 Ctrl+F5 一次即可永久修复）。

## 6. R17S4：口径选择器改为五类分组（2026-10-23）

- 新增 `data/caliber-groups.json`：以枪械表实际出现的 **29 个口径**为全集逐项人工归类，
  五个类别固定顺序：冲锋枪弹 / 手枪弹 → 步枪弹 → 霰弹 → PDW 弹 → 榴弹；
  每个口径带 `dia`（公称弹径 mm）用于组内排序，例外按真实弹径标注：
  `.366 TKM`=9.55mm、`.308 ME`≈7.82mm、`.338`=8.6mm、`.50 AE`=12.7mm、12g≈18.5mm、20g≈15.6mm、23x75=23mm。
- 霰弹按**实际口径**而非 Gauge 数字排序（12g 18.5 > 20g 15.6，23x75 最大）。
- 无法识别的口径不并入任何类别，单独放「未识别口径（未归类，需人工核对）」组（当前 0 个）。
- 口径筛选下拉改为 5 个 `optgroup`，组内按弹径降序；枪械下拉沿用同一排序。
- 具体弹药列表仍只显示当前枪械 `allowedAmmo`，仍按**穿透力升序**（未受口径排序影响）。

### 浏览器验证

- 分组标签：`["冲锋枪弹 / 手枪弹","步枪弹","霰弹","PDW 弹","榴弹"]` — 与期望完全一致。
- 组内降序：全部组 `dias[i-1] >= dias[i]` 成立（desc=true）；无未匹配口径。
- 5.45x39 筛选 → 15 把枪且口径一致；换枪 M4A1(24 弹匣)/AK-101(3 弹匣)/MP5 弹药列表随枪更新。
