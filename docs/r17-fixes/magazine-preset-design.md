# R17-C：预设压弹窗口（Top / Loop / Bottom）设计

参考图：`D:\personal\trae\02-塔科夫\ui图标\压子弹弹匣界面.png`（已确认存在并读取）。

## 1. 数据模型（`app.js` 状态 `s.magPreset`）

```
[ { zone: 'top',    ammoId, count },   // 第 1 行：最先射出的固定弹药
  { zone: 'loop',   ammoId, count },   // 第 2 行：循环（count = 该弹每轮发数）
  { zone: 'loop',   ammoId, count },   // 第 3 行：循环
  { zone: 'loop',   ammoId, count },   // 第 4 行：循环
  { zone: 'bottom', ammoId, count } ]  // 第 5 行：最后射出的固定弹药
```

- zone 的多重集恒为 `{top×1, loop×3, bottom×1}`：拖拽/按钮都是**交换两行的 zone 与配置**，
  不是 CSS 排序，也不是复制；
- 拖第 1 行到第 2–4 行：两行交换 → 原首发行变循环条目，原循环行接管「首发」身份；
  第 5 行同理；配置（弹药、数量）随行迁移，不丢失；
- 不依赖鼠标：每行都有等价按钮（首/末行「→ 循环」，循环行「→ 首发」「→ 末发」）。

## 2. 生成逻辑（`combat_sim.js` `CS.buildMagazineFromPreset(slots, capacity)`）

纯函数、无随机，固定输出顺序：

```
Top 固定区（min(count, 容量) 发）
→ Loop 循环区（填充剩余容量；模式 = 循环行按行序、每行 count 发；
   末轮不满整轮时按循环顺序截断，并给出 warning）
→ Bottom 固定区（min(count, 容量) 发）
```

显式拒绝（返回 `ok:false` + 中文错误，绝不静默）：
- Top+Bottom 固定发数 > 容量；
- 容量未知（`missing`，如内置弹匣枪械）；
- 预设全空。

显式警告（`warnings`，照常生成）：循环区为空时剩余 X 发未装填。

## 8. R17S2 二次修正：分区布局 / 全行拖拽 / 序列严格化（2026-10-23）

### 8.1 布局（对照参考图逐项实现）

- 三个**独立分区**，带标题与彩色分隔（首发=绿 / 循环=蓝 / 末尾=橙），
  不再仅靠序号区分角色；空分区显示虚线占位。
- 每行从左到右严格为：**角色标签 → 填装序号 → 弹药方框 → 弹药名（穿/伤）→ 数量 → 小叉叉**。
  换区按钮删除（拖拽是唯一换区方式，五行全部可拖）。
- 小叉叉：清空本行弹药 ID + 图标 + 名称 + 数量（`count=0`），不动其他行；
  实测点第 3 行后其余 3 个已填行不受影响。
- 弹窗：点击外部自动关闭（document mousedown，弹窗内部点击不误关），已选弹药不丢失。

### 8.2 拖放语义（amSimPresetDrop）

- 同区拖到某行 = 区内排序（splice）。
- 跨区且**目标区有空槽** → 配置迁移进空槽，**源行保留原角色并恢复为空槽**
  （配置不会同时存在于两个区）。
- 跨区且**目标区无空槽** → 整行迁移角色（配置随行加入目标区末尾）：
  循环行拖进已占用的首发区 = 首发区出现第二个条目，该弹不再参与循环。末尾区同理。
- 实测：行1→循环区后首发恢复空槽 ✅；再拖回可逆 ✅；循环行拖入已占用首发区 →
  首发区 2 个条目 ✅；循环区内两行交换后重新装填，第 4/5 发弹药随之互换 ✅。

## 10. R17S4：插入语义 / 循环 5 种 / 动态条目（2026-10-23）

### 10.1 根因

- 旧实现是「五槽位 + 空槽迁移」：跨区拖拽若目标区没有空槽，只能整行迁移并**追加到末尾**；
  循环区固定 3 行，无法容纳第 4/5 种弹药。
- 用数组下标识别行：跨区迁移后数组顺序变化 → 后续同区排序可能插入到错误位置（表现为「拖了但没变」）。

### 10.2 新模型

- `magPreset` 改为**可变长度条目数组** `{uid, zone, ammoId, count}`；分区只是条目的 zone 属性，
  渲染按 zone 分组、数组顺序即区内顺序。
- 每区底部「＋ 添加一行」按钮（循环区上限 5 个条目，满时 disabled + 提示）。
- 拖放统一为**插入**：跨区拖到某行 → 该条目 zone 改为目标区并插到目标行前/后（指针上下半部决定），
  源区少一个条目、**不留副本、不覆盖目标区已有序条目**；同区拖拽只重排。
- 循环区满 5 时：拖入被拒绝且原配置完全不变（flash 提示 + 添加按钮禁用）；引擎侧 `buildMagazineFromPreset`
  同样拒绝第 6 种（最后一道防线）。

## 11. R17S5：允许空行直接拖拽（2026-10-23）

### 11.1 根因

`amSimPresetDrop()` 开头有一句硬性拦截：

```js
if (!src.ammoId) { return { moved: false, msg: "这一行还没有弹药：先点方框选择，再拖动。" }; }
```

`dragstart` 本身没有限制（`row.draggable = true` 与是否已选弹药无关），所以空行能「拿起」，
但**落到目标位置时被 drop 处理拒绝**，用户看到的就是「提示 + 拖不动」。
同时跨区插入的上限判断用的是 `amSimPresetZoneCount`（连空行一起数），会把空行当成新增弹药种类。

### 11.2 修改（最小范围）

- 删除上面那句拦截；拖拽只负责「改分区 / 改顺序」，不再要求已选弹药。
- 新增 `amSimPresetZoneAmmoCount(s, zone)`：**只数已配置弹药**的条目。
  - 跨区拖入时，只有**带弹药的条目**才校验「该区已有 5 种弹药」；空行不受此限。
  - 空行只受行数保护 `AM_SIM_ZONE_ROWS_MAX = 8`（防止无限堆空行），与弹药种类无关。
- `sim-preset-add` 与「＋ 添加一行」按钮改用行数上限（含空行），循环区仍提示 5 种弹药上限。
- 选择弹药时（`sim-preset-choose`）新增校验：空行被填成弹药时，若该区已有 5 种弹药 → 拒绝并提示，
  **原配置不动** —— 保证「空行迁移不占名额」不能反过来绕过容量/种类校验。
- 拖拽提示文案区分空行：「（该行仍为空，可点方框选择弹药）」。
- 开始模拟/装填阶段仍由引擎校验：预设全空 → `预设为空：请先在任意行选择弹药与数量`。

### 11.3 真实浏览器验收（Chrome CDP，1500×1700）

拖拽方式：真实鼠标 `mousePressed` + 连续 `mouseMoved` 触发原生 `dragstart`（页面收到 `dragstart`、
`dataTransfer` 里是行 uid），随后由浏览器级拖拽事件（`Input.dragIntercepted` → `dragEnter/dragOver/drop`）
完成落点 —— 页面侧走的是与真人拖拽相同的 `dragover`/`drop` 监听，没有调用任何内部函数。
（注：无头 Chrome 对纯合成鼠标只派发 `dragstart` 不派发 `drop`，实测 dragover 2 次 / drop 0 次，
因此落点必须用浏览器级拖拽事件；这点已如实记录。）
