# R19 价格来源与成本规则

实现位置：`gun_builder.js` 的 `priceOf()` / `cost()`；界面在属性面板与对比表。

---

## 1. 本地只有一套价格，没有 PVP/PVE 之分

`data/items.json` 每个物品的 `p` 字段：

```json
"p": { "b": 31517, "l": 16000, "a": 44110, "lo": 16000, "hi": 299999 }
```

| 字段 | 含义 | 来源 |
|---|---|---|
| `a` | 跳蚤市场 24h 均价 | 构建期快照 |
| `b` | 基础参考价（basePrice） | 上游 |
| `l` / `lo` / `hi` | 最近最低价 / 24h 最低 / 24h 最高 | 构建期快照 |

**没有** `avg7d`、没有 PVP/PVE 双套、没有商人收购价（`Sell`）。

参考站的价格口径切换（`lastPrice` / `avg24h` / `avg7d` / `only FleaLvl` / `only TraderLvl`）
和页头的 `PVE`/`PVP` 开关，本地**无法复刻**，因为数据只有一套常规模式的四字段快照。

---

## 2. 取价规则

```
priceOf(item):
  1. p.a（跳蚤 24h 均价）有值 → 用它
  2. 否则 p.b（基础参考价）有值 → 用它
  3. 都没有 → null（记 missing）
```

**绝不返回 0**。缺价的配件：

- 不计入总价（`total` 只累加有价的项）；
- 单独计数 `missingPrice`，界面显示「（N 件缺价，未按 0 计）」；
- 概率性地整枪总价是 `null` 而不是一个偏小的数（当所有件都缺价时）。

---

## 3. 两种成本口径（可切换，规则写死在代码里也写在界面上）

| 口径 | 含义 | 用途 |
|---|---|---|
| `includeStock: true`（默认） | 枪械本体 + **全部**已装配件 | "整枪落地价"——照着这套配置从零买齐要多少钱 |
| `includeStock: false` | 只算**不在默认装配里**的件 | "改装花费"——已经有这把枪的人再改要花多少 |

第二种依赖 `stockIds`（默认装配的 itemId 集合），由 `gunDefaultBuild()` 提供。
界面同时在属性面板显示两行：「整枪成本（含原厂件）」与「其中改装件」，
避免用户把"改装花费 40,002"误读成"整枪只要 4 万"。

实测 AK-74 默认装配：

| 口径 | 值 |
|---|---|
| 含原厂件 | 84,112 ₽ |
| 其中改装件 | 40,002 ₽（默认装配本身就等于原厂，所以这 4 万是"买齐这些原厂件"里的非枪械部分） |

## 4. 与参考站的口径差异（如实标注）

| 项 | 参考站 | 本地 |
|---|---|---|
| 整枪价 | `Buy (42, 864)` | 84,112 ₽（同一把 AK-74 默认装配） |
| 差异原因 | 参考站默认按**商人可买价 + 等级限制**结算，且带 PVP/PVE 口径 | 本地只有跳蚤 24h 均价一种口径，且**不按商人等级筛选** |
| 单件价 | 候选表 `Prc` 列 + 商人图标 + 等级角标 | 候选表 `FLEA 价` 列，无商人来源与等级 |
| 卖出价 | `Sell ()` | **未实现** |

> 两者数值不同不是错误，是口径不同。界面上已经标注「价格档 FLEA：构建期快照，非实时行情」，
> 不把本地数字说成"实时价"，也不说成"和参考站一致"。

---

## 5. 商人等级筛选：为什么没做

要做"按商人等级筛可购买配件"，需要每个配件的 `{商人, 等级, 价格}` 三元组。
本地 `items.json` 的 `trade` 字段只有部分物品的购买报价（`{k:"buy", t:商人id, l:等级, c:货币, p:价格}`），
而 `p.a` 是跳蚤价，两者是**不同口径**。

用跳蚤价冒充"商人价"会误导用户，所以本轮：

- 候选表只显示 FLEA 价（并标注是快照）；
- **不**提供"只看 LL3 能买到的配件"这类筛选；
- 在 `feature-matrix.md` 里标为「参考站有 / 本地未实现」。

---

## 6. 价格时效

`items.json` 是构建期快照，界面上常驻一行：
「价格档 FLEA：构建期快照，非实时行情」。
不显示"更新于 xx 分钟前"这类暗示实时的文案。
