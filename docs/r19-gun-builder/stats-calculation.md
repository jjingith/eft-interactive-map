# R19 整枪属性计算规则与可信度

本文说明 `gun_builder.js` 里每个字段的**数据来源、公式、以及它到底有多可信**。
判定依据不是"看起来对"，而是拿 `data/gun-presets.json` 里 **373 条官方预设**
（每条都带完整装配清单 + 游戏内真值 `e`/`rv`/`rh`/`moa`）逐条重算比残差。

复现命令：

```bat
python tools/verify_gun_formula.py
node tests/js/gun_builder_test.js
```

---

## 1. 数据来源

| 文件 | 内容 | 采集方式 |
|---|---|---|
| `data/items.json` | 名称、价格、重量、槽位 `slots[].allow`、互斥 `conflictingItems`、`mod.e`、`mod.r`、弹匣 `cap` | 项目原有构建期快照 |
| `data/gun-presets.json` | 373 条官方预设：`g`(枪 id) / `n` / `e` / `rv` / `rh` / `moa` / `i`(path→itemId) | 项目原有构建期还原 |
| **`data/gun-stats.json`** | 枪械基础 `rv`/`rh`/`coi`/`rpm`/`sr`/`v0`/`preset`；配件 `rm`/`am`/`v0`/`e` | **R19 新增**：`tools/build_gun_stats.py` 从 `https://json.tarkov.dev/regular/items`（17.3 MB 快照）提取，采集日 2026-10-24 |

`gun-stats.json` 覆盖：**668 把枪**（`ItemPropertiesWeapon`）、**2507 个配件**
（`ItemPropertiesWeaponMod` 等）。本项目用到的 163 把枪 **全部** 有基础后坐力与默认预设
（163/163）。

## 2. 逐字段公式与验证结果

### 2.1 人机工效 Ergonomics —— `verified`

```
ergo = 枪械基础 e + Σ(已装配件 e)
```

| 指标 | 值（373 条样本） |
|---|---|
| 平均残差（计算值 − 真值） | **+0.002** |
| 中位绝对误差 | **0.000** |
| p95 | 0.100 |
| 最大 | 3.000 |

结论：加法模型成立，且**不存在额外的重量惩罚项** —— 我一度怀疑有
`-(总重 - 阈值) × 系数` 这样的项，于是按总重量分桶看残差（0.5 kg 一桶，
从 0.5 kg 到 13 kg），**每个桶的平均残差都在 ±0.1 以内且不随重量单调变化**，
所以判断为无重量项。那个最大 3.000 的离群点是个别预设里有配件在本地库里缺字段。

### 2.2 垂直 / 水平后坐力 —— `verified`

```
recoilV = 枪械基础 rv × (1 + Σ 配件的 recoilModifier)
recoilH = 枪械基础 rh × (1 + 同一 Σ)
```

| 指标 | 垂直 | 水平 |
|---|---|---|
| 平均残差 | −0.016 | −0.014 |
| 中位绝对误差 | 0.300 | 0.300 |
| p95 | 0.500 | 0.500 |
| 最大 | 0.500 | 0.500 |

关键点：**百分比先累加、最后乘一次**，不是逐项连乘。验证方法很有力 ——
同一个 `Σ recoilModifier` 同时解释垂直和水平两个字段的残差（两者残差分布几乎相同），
说明游戏内就是这么算的（若各配件独立连乘，两个方向的残差会发散）。
残差上限 0.5 来自游戏内取整。

### 2.3 重量 —— `verified`

```
weight = 枪械 w + Σ(已装配件 w)
```
纯加法，字段直接来自物品库，没有换算。

### 2.4 射速 —— `verified`

`fireRate = 枪械 rpm`（配件不改射速）。数据来自上游 `properties.fireRate`。

### 2.5 瞄准距离 —— `verified`

`max(枪械 sightingRange, 已装瞄具的 sightingRange)`。

### 2.6 弹匣容量 —— `verified`

取已装弹匣的 `capacity`；未装弹匣时返回 `null` 并标 `missing`，**不填 0**。

### 2.7 散布角（精度）—— `verified` 但**不做 MOA 换算**

只给上游 `centerOfImpact` 的原值（单位：度），越小越准。

**为什么不换算成 MOA**：试着用 `coi + Σ accuracyModifier` 拟合预设里的 `moa` 真值，
结果中位误差 2.5、p95 25.6、最大 42.4，且 `moa / (coi × 60)` 的比值在
**0.571 ~ 39.55** 之间浮动。说明 MOA 还依赖 `deviationCurve` / `deviationMax` 等
未公开的项，无法可靠反解。按任务要求「不确定就不要伪造精确值」，
所以界面显示「散布角 0.058 度」，并在 tooltip 里写明：
*"配件 accuracyModifier 合计 X，其与游戏内 MOA 的换算未确认，不做合成"*。

参考站的 `Accuracy 1.99` 是它自己的口径，本地不复刻、也不冒充。

### 2.8 初速 —— `missing`（未选弹药时）/ `estimated`（选了弹药时）

```
velocity = 弹药初速 v0 × (1 + (枪械 velocity + Σ 配件 velocity) / 100)
```

- 上游枪械的 `velocity` 字段实测是 **1.8、0** 这种小数值，判断为**百分比修正**而非绝对 m/s
  （绝对初速 890 m/s 在弹药数据里）。这个解释标 `estimated`。
- 没选弹药时直接返回 `null` + `missing`，不拿枪械字段冒充初速。

### 2.9 没有实现的字段（参考站有，本地无可靠数据）

| 字段 | 参考站 | 本地 |
|---|---|---|
| `EvoErgoDelta` | 有（如 33.8） | **无公式、无数据** → 不显示 |
| `ArmStamina` | 有（如 32.0s） | 无 → 不显示 |
| `100% Headshot acc` | 有（如 141m） | 无 → 不显示 |
| `ADS Time (beta)` | 有（如 0.56s） | 无 → 不显示 |
| `OverSwing` | 有（YES/NO） | 无 → 不显示 |
| MOA | 有 | 只给原始散布角，见 2.7 |

宁可少显示，也不让一个"看起来精确"的假值混进对比表。

## 3. 可信度三档在界面上的表现

| 标记 | 含义 | 出现位置 |
|---|---|---|
| `✓ 实测` | 字段直接来自游戏数据，公式经 373 条预设反证 | 人机工效 / 后坐力 / 重量 / 射速 / 瞄准距离 / 弹匣容量 / 散布角 |
| `≈ 估算` | 公式形式已知但某环节未核实 | 初速（枪械 velocity 按百分比解释） |
| `— 缺失` | 本地没有数据，返回 `null`，**不填 0** | 未选弹药时的初速、未装弹匣时的容量 |

对比表里，任一侧为 `null` 时该行**两边都不参与比较**，差值是 `—` 而不是 `0`，
避免"缺失值填零制造虚假优势"。

|---|---|---|
| Ergonomics | **47.0** | 47 |
| Ver Recoil | **71.0** | 71 |
| Hor Recoil | **180.6** | 181 |
| Weight | 3.32 kg | — |
| Mag capacity | 30 发 | — |

三个字段完全对上（参考站水平后坐力显示 181 是它自己四舍五入）。
这是独立来源的交叉验证，比只对自家预设残差更有说服力。
