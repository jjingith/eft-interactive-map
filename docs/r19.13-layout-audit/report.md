## 2. 前握把沿护木正下方纵向排列

链条来自真实 `node.parent`（不看 `foregrip` 分类做位置猜测）：从 foregrip 上溯到第三行主体件，中间各层沿**同一列**依次向下。

| 情况 | 链条 | 实测样例 |
|---|---|---|
| A 直接安装 | 护木 → 前握把 | 雷明顿 R11 RSASS：handguard r3c4 → foregrip **r4c4**（41 把） |
| B 上/下护木 | 上护木 → 下护木 → 前握把 | **浏览器现场演示**：M4A1 + DD RIS II 12.25″ 上护木 + 下护木 + BCM 前握把 → r3c4 → r4c4 → **r5c4**（`_accept.json caseB`，截图 `L-caseB-upper-lower-foregrip-1920.png`） |
| C 导轨转接 | … → 导轨 → 前握把 | SIG MPX：handguard r3c4 → mount **r4c4** → foregrip **r5c4**（11 把） |

不变量（全枪）：**0 例列不对齐、0 例在父件上方、0 例占 r2 或 r4c6–c9**。
不伪造导轨：转接层只在真实安装链要求时出现（数据里 `viaRail` 链的 mount 都是真实槽位）。

## 3. 枪口附件纵向链

`枪口 → 转接件 → 消音器…` 沿枪口正下方同列逐行展开（前照门/照门不进链，走第二行锚点）。
实测 **129 / 129 条链同列**（含 HK 416A5 / SPEAR 的 `mod_muzzle/mod_muzzle` 二级槽 → r4c1；PP-91-01 的二级枪口 → r4c2）。
层级超过 6 行时写 `exceptions`（"枪口链层级超过 6 行画布容量"），**不静默省略**。

## 4. 护木其余附件进第六行

护木子树里既非上方导轨、非前握把链、非前照门的槽位 → **第六行**空闲格，按槽位树顺序稳定从左到右（不随装卸重排）。
实测 **125 个护木附件中 118 个落 r6**，0 个横向漂移（其余为同基名空副本，按 `gwSlotVisible` 规则本就不显示）。
第六行不覆盖枪口链 / 前握把链 / 固定锚点（`freeAt` 排除 occupied+reserved）。

## 5. 优先级与稳定性

严格按任务书第五节 8 级优先级实现（固定网格 → 第三行主体 → 固定锚点 → 第二行锚点 → 枪口链 → 前握把链 → 第六行 → 其余空位）。
同一格只有一个槽位（`occupied` 表）；固定锚点不被普通附件挤走；布局只改视觉坐标，**不改物品 ID / 兼容性 / 父件 / 安装关系**。

## 8. 已知例外与数据缺口

1. **例外 6 条**（`slot-mapping.json → summary.exceptions`）：SCAR-H 等枪有 2 个前照门槽位（机匣 + 护木各一），按任务书只把第一个锚到枪口正上方，第二个按真实父子关系另行落位并记录。
2. **情况 B（上/下护木）在默认装配里 0 例**——本地 163 把枪的出厂默认都没有"上下护木+前握把"组合；但数据中存在 205 组真实结构（DD RIS II 上/下护木等），已用浏览器现场装配验证（caseB）。
3. 嵌套同名槽（照门上的照门）由"子件环"处理（照门子件 r2c7），不重复占用锚点。
4. 布局只动坐标；`gwLaneOf` 的车道语义与 R19.12 前握把钉位断言全部保留。
