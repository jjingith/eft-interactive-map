## 二、ASH-12 根因与修复

### 根因（两层）

1. **车道判定**：`gwLaneOf()` 把 `tactical/flashlight/laser` 一律归为 `lower`，根级（直接装在枪身上导轨）的战术装置因此没有「上方行」归属。
2. **找位函数越界**：`findFree(prefRow, prefCol, true)` 名为 `belowOnly`，实际仍会：
   - 扫同一行（`freeAt(prefRow, c)`）；
   - 兜底「从第 1 行开始找第一个空格」。
   ASH-12 的 `mod_tactical_001/002` 就是这样被塞进 **r3c3 / r3c1**（枪身主体行）。

修复前实测（`ash12-layout-audit.json` → `before.mainRowWas`）：
`r3c1 战术 → r3c2 枪口 → r3c3 战术 → r3c4 护木`，与游戏内不符。

### 修复（通用逻辑，非单车特例）

| 改动 | 位置 | 说明 |
|---|---|---|
| 根级战术装置归上方行 | `gwLaneOf()` | `tactical/flashlight/laser/devices/emitter` 且 `!parent` → `top2`；挂护木/转接件的仍走 `lower` |
| `belowOnly` 严格向下 | `findFree()` | 只在 `prefRow+1…6` 找位，不再回落同/上行 |
| 主体行压缩 | 主体链放置阶段 | 先收集全部真实主体槽位，按角色排序后统一分配列：多个槽位向枪身连续压缩（末列 = `body.col-1`）；单槽保留规范列 |
| 上导轨战术槽摆放 | 新增 4.4 阶段 | 第 2 行、前照门与瞄具之间（左→右稳定）；放不下转入 **第 6 行**（子弹行下一行），绝不回主体行 |

### ASH-12 修复后（浏览器实测）

```
主体行 r3: c4 枪口制退器 · c5 聚合物护木   （连续、紧邻枪身 c6）
战术槽   : r6c1 / r6c2 / r6c3               （上方行已满 → 备用车道，未进主体行）
行高      : [57.8, 57.8, 85.5, 57.8, 57.8, 57.8]  六行全非零
占位格    : 0
```

> 说明：ASH-12 的前照门在 `r2c4`（枪口正上方）、瞄具在 `r2c5`，二者相邻，第 2 行已无空位，因此战术槽按任务书 5.3 转入 r6。这是规则要求的降级路径，不是回填主体行。
