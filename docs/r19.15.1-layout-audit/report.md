## 1. 根因：布局只用了「父件」一个维度

`gwBuildLayout()` 的通用落位阶段只做一件事：`findFree(父件行, 父件列, belowOnly=true)` ——**父件在哪、子件就往下贴**。这解释了本轮全部四类错误：

| 现象 | 真实原因 |
|---|---|
| AXMC 上机匣掉到 r4c1 | 上机匣是「机匣槽套机匣槽」的内层，被通用规则当成普通子件，往父件下方找位，r4c5 被前握把占了就一路回绕到 r4c1 |
| AXMC 后托落 r5c8 | 后托槽的真实父件是**手枪式握把**，于是被排到握把下方；而枪托的视觉位置应固定在本体右侧 r3c9 |
| M10 镜座落 r4c5、瞄具 r5c5 | 镜座 lane 是 `top2`，但通用阶段不读 lane，仍按「父件下一行」放到本体行下面，瞄具再往下 |
| 马林击锤/击锤帽落左侧 | 击锤没有专属角色，被当普通附件；环状杠杆（真实 `charge`）占着 r2c9，把击锤挤走 |
| AK 燕尾槽基座落 r4c1/r4c5 | 同上：镜座类只认「子树里有瞄具槽」，空槽 + allow 直挂瞄具的燕尾槽基座既不被 4.5 收走，也不进 2 行 |

**修法不是给这几把枪加坐标，而是把「真实安装关系」与「视觉角色」分成两层**：

- 真实槽位树回答「装在哪」——一律不改；
- 新增显式视觉角色（写在 `L.cells[].role` 与 `L.roles` 里，可审计）回答「画在哪」。

## 2. 新增/改动的视觉角色（全部数据驱动，不看枪名/物品名）

| 角色 | 判定依据（真实数据） | 位置 |
|---|---|---|
| `receiverUpper` / `receiverLower` | 槽位基名属机匣类，且其父槽位也是机匣类 | 上机匣 r3c5、下机匣 r4c5（同列相邻） |
| `stockOnGrip` / `stockUnderParent` | 基名 `stock`（含 `stock_akms` 等变体）；无根级枪托时取「父件不是枪托」的第一个 | r3c9，子枪托 r4c9→r5c9 |
| `hammer` / `hammerCap` | 基名 `hammer` 且该枪有真实枪托槽；击锤帽 = 击锤槽的真实子槽 | r2c9 / r1c9 |
| `lever` | 同枪有真实 `charge` 槽且击锤链占用本列上方 | r4c9（枪托正下方） |
| `trigger` | 基名 `trigger` 且该枪**没有**后握把槽 | r4c8（本体下方三格最右） |
| `topOptic` | 基名 `mount/scope/sight_*`、lane 为上置；mount 需子树含瞄具槽 **或** allow 里的候选件自带瞄具槽；父件是护木的顶盖除外 | 父件（或机匣列）上方，逐层向上，超顶则扩展 |
| `dovetailMount` | 基名 `mount` + 父件是机匣/根级 + allow 里**直接**列着 `pt=Scope` 物品 | r2，按该行真实槽位序号取第 3 位 |

配套的两条硬护栏：

1. **主体行独占**：r3 只允许主体链角色（枪口/导气箍/枪管/护木/机匣/上机匣/枪托）。父件被搬到第 2 行后，它的下挂件原本会顺着「父件下一行」落进 r3（AUG 的 `mod_tactical`、KRISS 的上导轨战术件都中招过），现改为「父件同行相邻 → 父件上方 → 本体行下方」。
2. **上置件的子槽继续向上**：父件行 ≤ 2 时，子槽优先排到父件上一行（前握把/脚架/弹匣除外）。

### AK 燕尾槽基座（28 把枪 / 32 个真实槽位）

- 识别口径：`mount` + 父件是机匣或根级 + `allow` 里直接列 `pt=Scope` 物品（AK-74N 的 `mod_mount_000` allow 19 项里 18 个是 `Scope`，另 1 个是「Axion Kobra 燕尾槽适配导轨基座」）。
- 结果：**32/32 全部落在 r2（本体正上方一行）**，槽位路径/ID/allow 未改，未新建任何槽位。
- 基座上的真实瞄具子槽继续向上（装 PSO-1 后其 `mod_tactical` 落在 r1c5，而不是回到本体行）。
- **序号说明（需产品确认）**：规则要求「该行从左第 3 个真实槽位」，实测 32 个里有 31 个是第 1/2 位。原因不是实现取巧，而是这些 AK 的第 2 行真实槽位只有 3–4 个（基座 / 照门 / 照门副本 / 拉机柄），基座左侧没有任何槽位；要变成第 3 位只能把它排到照门右边（物理上错）或凭空造槽位（规则明令禁止）。当前实现取「机匣正上方的光学带（r2c5/c6）」并逐枪记录序号。

## 4. 全量审计（163 把枪）

判定方式：用 localStorage 里**应用真实的默认装配清单**重建槽位树 → 重算布局 → 与真实 DOM 逐格比对。

| 检查 | 计数 |
|---|---|
| DOM 槽位集合 ≠ 布局输出 | 0 |
| DOM 坐标 ≠ 布局坐标 | 0 |
| 重复槽位 / 格子重叠 / 越界 | 0 / 0 / 0 |
| 行高塌缩 | 0 |
| 主体行不连续 / 未紧邻本体 / 顺序错 / 非主体链入侵 | 0 |
| 镜座或瞄具低于本体行 | 0 |
| 枪托不在第 9 列 | 0 |
