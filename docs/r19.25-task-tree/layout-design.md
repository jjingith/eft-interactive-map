# R19.25 任务树布局设计

- 实现：`js/task-graph-layout.js`（纯计算模块）+ `tasks.js` 的渲染层
- 审计与根因：`docs/r19.25-task-tree/audit.md`
- 指标对比：`layout-before.json` / `layout-after.json`（同一个审计脚本跑出来的）

---

## 一、要解决的问题（不是"调间距"）

旧实现的病根是**把 293 条互相独立的任务线当成一棵树来排**：

- 300 个"没有前置"的任务全在第 0 列 → 18000px 高的竖条；
- 列内按商人/等级排序，与父子关系无关 → 974 处直线交叉；
- 跨层边用贝塞尔直连 → 32 条边压在卡片上；
- 真实图是 293 个弱连通分量（最大 29 个节点，246 个孤立单点）。

所以"把节点间距调大"没用，必须换排布模型。

---

## 二、算法（分层 + 分块，Sugiyama 的工程化子集）

### 2.1 五步

```
① 建图      只取前置边（and / or）做分层；失败分支单独收集为"辅助边"
② 分量      无向连通分量 = 一条任务线；孤立任务自成一个分量
③ 分层      分量内最长路径分层（Kahn 拓扑）；DFS 找回边，回边不参与分层但照画
④ 排序      分量内多层扫描：中位数(median) 上/下扫 + 相邻交换(transpose)，取交叉最少的一版
⑤ 打包      分量作为"块"，按主商人分带；带内从左到右排块，超宽换行；块内逐层落坐标
```

### 2.2 关键设计决定

| 决定 | 理由 |
|---|---|
| **分量当"块"，不跨块排层** | 264 条边里有 63 条跨商人、但**没有一条跨分量**。块内排层 → 连线永远在块内，不会出现横跨全图的斜线 |
| **按商人分带** | 16 个商人 = 16 种发布来源，是玩家最自然的心理分组（参考站也用商人分组）；带标题直接写英文原名 |
| **跨层边补哑节点** | 标准 Sugiyama 做法：把 A→C（跨 2 层）拆成 A→d→C，哑节点占位后每条边只跨一层，正交折线不会穿过中间卡片 |
| **失败分支不参与分层** | 它是"某个任务失败导致本任务失败"，不是"解锁"关系；真实数据里失败分支**存在环**（互为失败条件），参与分层会把图搅乱 |
| **正交折线** | 参考站实测就是这样画（path 只有 M/V/H）。正交线在密集图里比贝塞尔读起来干净得多 |
| **块内排序用中位数而非重心** | 中位数对单个离群邻居不敏感，503 节点规模下更稳 |

### 2.3 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `nodeW` / `nodeH` | 176 / 48 | 与渲染层共用，改一处即可 |
| `gapX` | 54 | 层间距（给正交折线的竖直通道留空间） |
| `gapY` | 14 | 同层节点间距 |
| `blockGapX` / `blockGapY` | 30 / 26 | 块之间的横向/纵向留白 |
| `bandHeadH` | 26 | 商人带标题高度 |
| `maxBandW` | 2600 | 带内换行宽度预算（超过就换行，避免一条带无限宽） |
| `dummyH` | 10 | 哑节点占的高度（不画出来，只占位） |

### 2.4 连线画法

一跳（父 → 子，且相邻层）：

```
父右中 ──水平──> 层间通道(midX) ──竖直──> 子中线 ──水平──> 子左中  ▶
```

- `midX` 取层间距中线，并按边序号做轻微车道偏移（`lane * 4px`），避免多条边的水平段完全重叠；
- 跨度 > 1 的边经过哑节点，折点逐个拼接，形成阶梯；
- **回边/环边**：从父右侧绕到 `max(x)+24` 再回到子左侧，虚线 + 独立箭头；
- **失败分支**：从父节点底部出线，走"下半通道"，红色点线；
- **跨商人依赖**：额外加 `is-cross`（点划线），提示"这条边连到别的商人的任务"。

### 2.5 降级策略（可解释，不静默）

| 情况 | 处理 | 记录位置 |
|---|---|---|
| 前置指向不存在的任务 | 丢弃该边，计数进 `metrics.dropped` | `metrics.dropped`、`droppedEdges[]` |
| 自环（A 的前置是 A） | 丢弃 | 同上 |
| 前置成环 | 分层时把回边标 `cycle`，**照样画**（虚线），不删边 | `metrics.cycles` / `metrics.cycleEdges` |
| 超级大分量 | 允许单块超出 `maxBandW`（不改结构，只让画布变宽） | 画布宽度 |
| 名称过长 | 节点内按 14 字截断，且**不会截成纯英文**（原文含中文时至少保留 1 个汉字）；全文在悬停里 | `clampLabel()` |
| 布局模块未加载 | 画布上直接显示"布局模块未加载"，不留空白 | `renderTree()` |

### 2.6 稳定性

- 所有排序都有确定性 tie-break（id / 名称 / 层级），同一份数据两次布局**逐坐标一致**（有测试）。
- 布局按 `mode + 任务数` 缓存（`state.layoutCache`）：切换状态、筛选、搜索**不重排**，
  只有换模式或换数据集才重算（503 节点约 60–170ms）。
- 搜索/缩放/拖拽只改相机，不改节点坐标 —— 依赖关系不会因为交互而"变形"。

## 四、为什么这样就不会"乱"了（逐条对应验收标准）

| 验收要求 | 现在的做法 |
|---|---|
| 同一任务线连续 | 一条任务线 = 一个块，块内从左到右就是任务推进方向 |
| 前置/后续相对位置易读 | 父节点永远在子节点左边（分层保证），箭头方向即依赖方向 |
| 多分支有合理间距 | 同层节点固定 `gapY`，块之间 `blockGap*`，不会挤在一起 |
| 多前置汇合清晰 | 多个父节点连到**同一个**子节点（ID 唯一，不复制节点），连线在子节点左侧汇聚 |
| 降低交叉 | 中位数 + 相邻交换，实测交叉下降 90%+ |
| 避免长距离连接 | 跨分量不存在边；长边用哑节点走层间通道，不横穿全图 |
| 节点不重叠 | 分块 + 分层格点，`metrics.nodeOverlaps === 0`（测试与浏览器双重断言） |
| 连线不穿关键文字 | 正交折线走层间通道；直线估算的穿节点数从 32 降到 23 |
| 尺寸变化可重算 | 宽高是布局入参，`buildGraph()` 按模式缓存，换数据即重算 |
| 搜索/缩放不改关系 | 只改相机（`state.cam`），节点坐标与边集合不动 |
| 改一条线不整图重排 | 块的位置由"带 + 排序"决定，改一条边只影响它所在块的内部次序 |

## 五、已知限制（不粉饰）

1. **"适配全图"在 503 节点下仍然看不清字**（全图缩放约 0.2）。这是信息密度的物理限制，
   参考站也一样。默认视角改为落在第一条商人带（0.72 倍），要看全貌再点"适配全图"。
2. **单块过宽**：最大分量 29 个节点跨 18 层，块宽 4086px，把画布撑到 4118px。
   没有做"长链折行"（会打断"一条线连续"的语义），代价是横向滚动。
3. **块内打包是货架式（shelf packing）**，不是最优装箱，带内会留下一些空白。
4. **跨商人边只做线型区分**，没有做"绕开无关块"的通道规划；它们仍然会穿过同一带内的其它块的空隙。
5. **没有按章节/主线分组**：上游任务数据没有章节字段，只有商人归属，所以不能凭空造章节。

## 六、R19.25.1 最终走线规则（覆盖 §2.4 的第一版描述）

第一版的"行间轨道"只服务长边，失败分支/回边仍按源行横穿 → 穿卡。最终规则：

1. **竖向走线只允许在列间通道**：`x = 层右边界 + gapX/2 + lane×2.5`（lane ∈ ±10，21 道）。
2. **横向走线只有两种**：① 端口到通道的短段；② **块顶母线** `y = 块顶 + routePad + 3 + lane×2`
   （lane ∈ ±23，只服务失败分支/回边，永远在所有节点上方）。
3. **长边**由哑节点拆成逐层相邻跳（每跳都落在通道里），不画横贯整块的长横线。
4. **回边与失败分支**：右出 → 通道 → 块顶母线 → 入通道 → 左进；不经过任何节点行。
5. **最后一列没有右侧通道**时走块外走廊（`x = 块右 + 8 + lane×2`），走廊按**全局 x** 分道，
   跨块也不重叠；`lt=0` 的入端同理走左走廊。
6. **端口偏移**：同父多出边 / 同子多入边按 6px 错开（±12 内），避免端口挤成一坨。
7. **车道分配确定性**：按占用区间依次试 0, +1, -1, +2, -2…，同一输入必然同一结果。

**失败分支与回边不参与分层**：只有 `prerequisites` 的 and/or 边进入最长路径分层；
`failedConditions` 只以 `kind=fail` 画出来（点划线 + 红箭头 + 悬停说明），
不抬高层级、不改可接取判定、不与普通前置混用线型。数据成环时回边单独画（`is-cycle`），
回边不删、前置图仍按 DAG 分层。

**孤立任务**（成员数 = 1 的分量）在所属商人分带内做密集网格（列距 nodeW+14、行距 nodeH+8），
不独占行；分带背景宽度按内容收口。

### 6.1 为什么线段不可能穿卡
节点只占"行区间"（y ∈ [rowTop, rowTop+nodeH]）；通道 x 落在列缝（gapX=54）内，
母线 y 落在块顶 routePad 区，长边的竖向移动只发生在通道内。折线段要么贴缝、要么贴端口，
几何上没有落进卡片矩形的可能。这条结论同时被：
布局模块 `edgeNodeHits` 指标（Node 全量）与浏览器 DOM 实测（`layout-after2.json`）证为 **0**。

### 6.2 稳定性
- 分层/排序/分带/车道全部纯函数；`ids.sort()` + 稳定比较器 + 占用表按插入序遍历。
- 同输入两次布局逐点一致；打乱任务对象键序也不变（`tools/r1925_layout_test.js` 有断言）。
- 布局结果按 `mode + 任务数 + 数据生成时间` 缓存；选中 / 搜索 / 缩放 / 模式往返**不重排**
  （浏览器验收 H1 逐点比对坐标）。
