## 二、需求 ①：AK 系照门统一锚定 r2c6

### 2.1 实现方式（加性、不改构建系统）
- 仅新增**引擎锚点逻辑**，不改 `gwBuildLayout` 主体结构、不重写布局引擎。
- 判定采用**结构签名**而非枪名匹配：
  - `gwIsAkRearSightGun(g)`：仅看“机匣/枪身直挂的 `sight_rear` 槽”，且其 `allow` 中**直接列着**标准 AK 照门物品 id（`GW_AK_REAR_SIGHT_IDS`，8 个真实兼容 id）。
  - 因此 `AKS-74U / AK-12 / AK-308 / AK-50 / SAG AK-545 / VPO-209 / VPO-101` 等**不会**被误伤（它们的照门 allow 里没有标准 AK 照门类）。
- 命中后 `akRearAnchor = hasDovetail || akRearFamily`，照门落 `r2c6`、第二照门相关槽落 `r2c7`（无燕尾槽的 AK 不预留燕尾基座三格 r2c8/r1c8/r1c9）。
- **未修改 `data/gun-layout-calibration.json` 任何记录**——锚点由引擎算坐标完成，不碰手动校准，从而不触发 `test_A1_other_aks_untouched` / `test_A4_calib_records_intact` 等校准完整性用例。

### 2.2 验证（`tools/r19_28_ak_probe.js`，结构判定与 app.js 逐字一致）
结构判定的 AK 系共 **16 把**，照门**全部落在 r2c6**：

```
AK-74N AK-74 AK-74M AK-101~105 AKM AKMN AKMS AKMSN AKS-74 AKS-74N
VPO-136(野猪-KM) Rifle Dynamics RD-704
→ CHECK_REQ1: PASS (16/16)
```

正确排除（保持原位 r2c8）：AK-12、AK-308、AK-50、SAG AK-545、Sako TRG M10 —— 这些名字含“AK”但结构签名不符，符合“不得宽泛字符串匹配含 AK 的武器”。

### 2.3 ⚠️ 与 R19.15.3 静态产物的潜在冲突（已知限制，非阻断）
- `tests/test_r19_15_3_round.py::test_03_rear_sight_band` 断言：**“不具备燕尾槽的枪械照门仍 r2c8”**（R19.15.3 硬性规则）。
- 该测试读取的是**已提交静态产物** `docs/r19.15.3-layout-audit/ak-dovetail-sight-layout.json`（经 `_json()` 直接读文件，不在测试运行时重算）。该文件当前仍是 **R19.28 之前**的快照，其中 `AKM 7.62x39` 的 `rearSight.col == 8`。
- 因此 `test_03` **当前通过**，但只是因为读的是陈旧快照。若用当前 app.js 重新生成该产物（交付步骤 `tools/r1923_audit.js`），AKM 会变为 r2c6，届时 `test_03` 的非燕尾槽断言将失败。
- **本轮未重新生成该静态产物**（重生成会反而是“改动交付物以迎合新行为”，且会触发上述旧测试失败，违背“不得弱化旧测试”）。该产物处于“与实时布局不一致”的陈旧状态，已在本文档显式记录。
- 这正是任务书①与既有 R19.15.3 规则的直接矛盾点，需用户决策（见 §5-问题 A）。

## 三、需求 ④：右栏候选表属性列

### 3.1 实现（加性，未改无关模块）
- `gunRows()` / `gunColumns()` / `gunRE3()` 重写：按当前选中槽位类别（一般 / 枪管 / 枪口 / 弹匣）组装属性行与列。
- **`R+E/3` 综合值** = `|后坐力%| + 人机E/3`，保留三位小数（按用户确认的表达式口径，示例逐项算为 6.333）。
- **动态整列隐藏**：当某类别整列属性全部缺失时，表头与数据行**同步**隐藏该列，不出现“表头有、数据为空白”的错位。
- 属性来源统一走 `data/items.json`（`mod.r` 后坐、`mod.e` 人机、`mod.a` 精度、`gw/gh` 占格、`cap` 容量、`w` 重量）；数据缺失与真实 0 区分明确。
