## 四、本轮改动

### 4.1 文件清单

| 文件 | 改动 |
|---|---|
| `app.js` | ①`createTable` 新增**虚拟排序键**支持（`opts.sorters` + `setSort(key,dir)` + `sortKey()`），并在 `setColumns` 时保留虚拟键；②配装表注册 `mov/turn/ergo` 三个排序器；③`gearRows()` 接入 5 个筛选；④新增 `renderGearFilters()` 与事件接线 |
| `index.html` | 候选表上方新增 `.lw-filters` 筛选条（5 控件 + 3 排序按钮 + 状态文字） |
| `style.css` | 新增 `.loadout-workbench .lw-filters / .lw-fl / .lw-sortbtn / .lw-fl-state`（作用域限定在配装工作台） |
| `tests/test_r20_6_preset_parity.py` | 新增 17 项测试 |
| `tools/r206_accept.py` | 新增真实浏览器验收（13 项） |

### 4.2 关键实现取舍

- **筛选只影响显示**：五个筛选全部是 `gearRows()` 里的 `continue`，不改兼容性判断、不改已装备状态、不写任何数据文件。清空筛选后条数回到基线（验收 L10 已断言）。
- **惩罚口径要说清**：`pen.s/t/e` 实测 216/244/330 条**全部为负分数**（如 -0.09 = -9%），所以「惩罚 ≤ X%」取 `-(s+t+e)*100`，不是直接相加。
- **商人等级复用同一函数**：`traderMinLevel(rec)` 与配枪候选表是**同一个函数**（测试断言全项目只有一份定义），避免两个页面口径漂移。
- **分项排序不占列**：参考站是「一列合显三值 + 三个排序按钮」，本地照做——虚拟排序键不新增列，只是让 `sorted()` 能按 `speed/turn/ergo` 单值排序；同键再点 = 反向，与点表头行为一致；按钮高亮**读表格真实 sortKey**，所以点表头排序时按钮也会跟着变。

## 六、明确不做（附原因）

1. **`only FleaLvl`**：本地 `items.json` 没有「跳蚤等级」字段，无法可靠判定；不拿别的字段冒充。已有「只看有报价」可覆盖最接近的需求。
2. **行尾 `✕` 屏蔽**：参考站该按钮点击后的效果未能在本轮确证（是「从本次预设里屏蔽」还是「永久黑名单」），按「不猜语义」原则暂不实现。
3. **`Buy ()` 括号件数**：参考站括号里是件数，本地 Buy 格已给「总额 + 缺价件数」，补件数需要改 `equippedTradeTotals` 的返回结构；价值低、风险中等，留待确认后再做。
4. **`Min Built-in` 的精确口径**：参考站该字段可能指「内置护甲值」而非「防弹等级」。本轮按**本体防弹等级**实现并在 tooltip 写明口径（不含插板）；若你要的是别的量，改一个取值函数即可。

## 八、R20.6b 补正：两处先前没讲清的地方 + 跳蚤等级落地（2026-10-29 续）

### 8.1 纠错①：候选表最右那个红叉 = 「没有任何价格」，不是屏蔽

上一轮报告把行尾的红叉写成「行尾 `✕` 屏蔽」。实测放大后确认：**那一列是 `Price`**，
红叉出现在「跳蚤价 / 商人买入价 / 兑换价全都没有」的行里，是价格单元格的状态图标，
点不动，也不会把物品从预设里移除。**本地不需要补「屏蔽」功能**；本地表格对同一种情况
显示「—」并在悬停写明「没有该档报价」。

→ 图：`docs/r20.6/explain/01-x-is-no-price.png`

### 8.2 纠错②：`Min Built-in` 过滤的是「本体防弹等级」

放大筛选条 + 表格分组行可以看到候选表按 **`Armor Class 5 / 4 / 3`** 分组，
`Min Built-in` 就是这组的下限（本体防弹等级，不含已安装插板）。
本地 **R20.6 已按 `baseArmorClassOf`（本体防弹等级）实现，口径一致，无需改动**。

→ 图：`docs/r20.6/explain/02-minbuiltin-flealevel.png`

### 8.3 跳蚤等级：上游有数据，已落地

**数据事实**（`https://json.tarkov.dev/regular/items`，2026-10-29 实测）：

- 字段名 **`minLevelForFlea`**，5480 件物品**全部**有值；
- 取值只有 `0 / 20 / 25 / 30 / 35 / 40`，分布：
  `0 → 2558 件`、`20 → 1036`、`25 → 1519`、`30 → 284`、`35 → 32`、`40 → 51`；
- `0` = 无限制（可自由上架）；抽样核对：`Rys-T / Altyn = 20`、`Vulkan-5 / DevTac = 40`；
- 这不是上游没有，而是本项目 `data/items.json` **归一化时没有保留该字段**。

**落地方式（不动 items.json 的 sha256 契约）**：

| 文件 | 作用 |
|---|---|
| `tools/r20_fetch_flea_levels.py`（新增） | 抓上游 → 校验（数量下限 / 字段类型 / 全量统计）→ 原子写 `data/flea-levels.json`；当天已生成则跳过；失败不写盘 |
| `data/flea-levels.json`（新增，158.5 KB） | `schema / source / field / fetchedAt / counts / levels / items`；逐件 `id → 等级`；运行期只读、不联网 |
| `app.js` | 新增统一读取层 `fleaLevelOf(id)`（**缺失返回 null，不当作 0**）；启动时可选加载；配装筛选条新增 `跳蚤等级 ≤` 下拉，选项**按真实数据动态生成并带件数**；数据缺失时控件自动禁用并把已有条件归零 |
| `index.html` / `style.css` | 筛选条新增该下拉（沿用既有 `.lw-fl` 样式，无新样式） |
| `tools/r20_validate_data.py` | 白名单纳入两个 sidecar，并新增 `OPTIONAL_FILES`：**可选缓存缺失记 skipped 而不是 error**（应用会自动降级） |

**筛选语义**：只显示「上架跳蚤所需等级 ≤ 所选值」的物品。`0`（无限制）永远通过；
本地没有该件记录时按「不可判定」筛掉（不猜成 0）。
