# 配装页右侧属性列为什么放不下 —— 实测对照

> 全部数字来自浏览器实测（`getBoundingClientRect` / `scrollWidth` / `clientWidth`），
> 不是估算。测量脚本：`tools/r207_cdp.py` + 一次性 eval。

## 1. 先看本地：21 列、1613px，容器只有 1041px

视口 1504×965，左侧装备栏占 457px，右侧表格容器 `#gear-table` 只剩 **1041px**。

| 指标 | 值 |
|---|---|
| 表格容器 `.tbl-scroll` clientWidth | **1039px** |
| 表头 `.tbl-head` 实际宽度 | **1613px** |
| 表头右边界 | x = **2071**（容器右边界 1497） |
| 溢出 | **574px** |
| 列数 | **21** |
| 横向滚动条 | `overflow-x: auto` 有，但 `scrollHeight` = **2033px**，滚动条躺在内容最底部 |

列宽明细（来自 `--tbl-cols` 网格定义）：

```
图标 44 · 名称 203 · 基础防弹等级 88 · 移动/转身/人机 104
前插板 40 · 后插板 40 · 左侧板 40 · 右侧板 40          ← 160
内衬材质及总耐久 118
前内衬 64 · 后内衬 64 · 左内衬 64 · 右内衬 64
脖颈内衬 64 · 左肩内衬 64 · 右肩内衬 64 · 前裆内衬 64 · 后裆内衬 64   ← 九个，共 576
防护区域 60 · 重量 60 · 获取方式 200
```

**九个内衬列 = 576px，占了溢出的 574px 的 100%**。换句话说：不折叠内衬，21 列在任何
常见窗口下都塞不进右栏。

## 2. 为什么"看不见"而不是"能滚"

`.tbl-scroll` 同时管横向和纵向（`overflow: auto`）。横向滚动条出现在**整个滚动内容的底部**，
也就是 `scrollHeight = 2033px` 的位置 —— 要先纵向滚到第 50 行附近才看得见那条横向滚动条。
实际浏览时永远够不到，于是表现就是**右侧列被直接裁掉**（截图 `r207-50-local-overflow.png`：
最后一列可见的是「脖颈内衬」，右边还有 7 列完全不见）。

## 3. 参考站怎么装下的

db4tarkov 在 1440P 下的护甲表（截图 `r207-53-db4-wide.png`）：

| 指标 | db4 | 本地（折叠前） |
|---|---|---|
| 列数 | ~19 | 21 |
| 表格宽 | 832（逻辑） | 1613 |
| 名称列宽 | ~93 | 203 |
| 插板列宽 | ~29（一个色块 + 一个数字） | 40 |
| **内衬细分列** | **0 个** | **9 个** |
| 横向溢出 | 无 | 574 |

它靠三件事：**列宽压到 20–40px**（插板列只有一个色块加一个数字）、**名称列两行换行**、
**根本不设内衬细分列**（内衬信息折进 Material / Eff Dur 两列）。

## 4. 修法：默认折叠九个内衬明细列

`state.lwLinerDetail`（默认 `false`）+ 筛选条上的「内衬明细」复选框。

- **折叠**：21 列 → 12 列，表宽 **1037px / 容器 1039px**，`scrollWidth == clientWidth`，
  溢出 0，最右边的「防护区域 / 重量 / 获取方式」全部可见（截图 `r207-52-folded-final.png`）。
- **展开**：勾上回到 21 列（1613px），保留完整能力，需要横向滚动。

实现上有一个刻意的分层：

```js
gearColumns(node, mode)          // 永远返回完整 21 列（列定义/顺序是既有契约，T24 / R11 测试钉着）
visibleGearColumns(node, mode)   // 渲染层按开关过滤掉 liner_* 九列
```

折叠只发生在渲染层，**列宽默认表、拖拽宽度、排序键、插板弹窗的列集都不受影响**。

## 5. 还可以继续做的（按性价比排序）

1. **压窄内衬列**：64 → 40px，九个共省 216px。展开时溢出从 574 降到 358。
2. **名称列 203 → 170**、**获取方式 200 → 150**：再省 83px。
3. **双轴滚动拆分**：外层横向、内层纵向，滚动条常驻视口底部。要重写 `createTable` 的 DOM 壳
   并同步两层的 `scrollLeft`，改动大、表头 sticky 容易出问题，暂不做。
4. **列显隐设置面板**（像 IDE 的列选择器）：用户自己决定显示哪几列，比全局开关更细。

前两条是纯 CSS/列宽调整，风险低；第 3 条建议只在确实要"一屏看全 21 列"时再做。

## 6. R20.7d 像素级复刻：行高 + 名称列窄而双行

### 6.1 参考站实测值（1440P，CDP 直接读语义节点 rect）

| 元素 | 实测 |
|---|---|
| 护甲行 `group` | 高度 **52**（`(1296,157) 1248x52`） |
| 插板格 | **52×52**（`(1028,157) 52x52`），四个格子 |
| Name 列 | 宽 **130**（表头 `button (789,102) 130x27`） |
| Mov/Turn/Erg | 148 · Material 60 · Eff Dur 40 · Capacity 24 · SE 24 · Kg 40 · Price 160 |
| 名称单元格内容 | **两行**：第一行短名、第二行全名 |

行高 52 与插板格 52×52 严格相等 —— 参考站是让插板格撑满整行的。

### 6.2 本地改了什么

| 项 | 改前 | 改后 |
|---|---|---|
| `--lw-table-row-height` | 40px | **52px**（插板格 `calc(行高 - 1px)` 自动跟着变 52×52） |
| 名称列宽 | 203–300px（吃满余量） | **150–170px**（渲染层钉住） |
| 名称单元格 | 单行全名 + 省略号 | **两行**：粗体短名 + 灰色全名 |

**短名从哪来**：不用数据里的 `shortName` —— 本地 `items.json` 的 `sn` 字段实测是
`"545cdb794bdc2d3a198b456a ShortName"` 这种「id + 字段名」的占位串，不可用；而
`items.json` 已进 SHA-256 契约，不能为了修这个字段重建整份数据。
改为从中文全名推导：截掉第一个中文括号之前的内容，取其中**连续的英文/数字/点/连字符片段**
（遇到中文即停）：

```
"6B43 屏障-Sh 防弹衣（数码丛林迷彩）"        → 6B43
"FORT Redut-T5（堡垒-T5）防弹衣（烟雾迷彩）"  → FORT Redut-T5
"LBT 6094A Slick 插板背心（橄榄绿）"          → LBT 6094A Slick
"5.11 Hexgrid 插板背心"                      → 5.11 Hexgrid
```

### 6.3 两个必须绕开的坑

1. **别用「列宽版本号」整批作废旧列宽**。第一版想用 `COLW_VERSION` 把上一套规格的
   `n=203` 一次性清掉，结果直接打破「用户拖过的列宽优先」这条持久化契约
   （`test_app_js_col_width_persisted_per_category`、`test_slot_driven_model_dynamic` 的
   U5 / T24 四处断言挂掉）。**撤回**了版本号机制，改成：
   - 渲染层（`visibleGearColumns`）钉住名称列宽度，`gearColumns` 与默认列宽表一字不改；
   - 一次性清掉配置里那条历史脏数据（服务端 `%APPDATA%\EFTMap/eftmap.config.json` 的
     `ui.colw` 与浏览器 `localStorage` 里的 `eftmap.colw`，备份 `*.bak-r207`）。
2. **CSS 规则有更具体的选择器压着**。`.tbl-row .tbl-cell[data-key="n"] > span` 里带着
   `white-space: nowrap`，会把名称的两行规则盖掉（computed style 会显示 `nowrap`）。
   两行规则必须写成 `.tbl-row .tbl-cell[data-key="n"] > span.lw-name-plain` 才压得住。

## 7. R20.7e 像素级复刻：图标 / 防护区域 / 内衬九列

用户反馈三条：
1. 防护区域和装备的图标太小；
2. 防护区域图标要**统一扣掉黑底**，仿照参考站；
3. **内衬属性不许删** —— 要改成参考站那样，不是砍掉。

### 7.1 参考站实测

| 元素 | db4（1440P） | 本地（改前） |
|---|---|---|
| Icon 格 | 图标 ~46×46 **深色底**，叠「短名（白粗体）/ 材质徽章（紫方块）/ 耐久（右下）」 | 图标 30×30，无叠加 |
| Zone（防护区域） | **白色护甲剪影 + 透明底**，高 ~40–50px | 22px、深色底不透明 PNG |
| 内衬九列 | **在表里**，窄列（~38px），格内两行（罗马等级 / 耐久），表头是部位剪影图标 | 64px 宽、表头文字、格内一行「III 85」 |
| 全表 | 19 列 / 1248px | 21 列 / 1613px |

### 7.2 改动

**① 防护区域图标扣黑底**（资源层）

新增 `tools/r20_7_strip_zone_bg.py`：按亮度分档处理 `assets/icons/zones/*.png` ——
亮度 < 96 的底色置为透明，≥ 150 的剪影提亮 1.35 倍（逼近参考站的白色剪影），
中间调做 alpha 过渡避免锯齿。原图备份在 `assets/icons/zones-orig/`（脚本可重复执行，
已处理过的会跳过，除非 `--force`）。
对照图：`screenshots/r207-75-zone-bg-compare.png`。

**② 图标放大**：`--lw-table-row-height` 已经是 52，装备图标 30 → **44px**（`.tbl-icon`），
防护区域图标 22 → **40px**（`.lw-zone-ico`）。

**③ 图标格叠加信息**（参考站的 Icon 格结构）：物品图上叠
- 顶部：短名（白色粗体 + 黑描边）
- 左下：材质徽章
- 右下：耐久数字

物品图是浅色底，所以格内压了一层 `rgba(16,20,24,.55)` 深色半透明，和参考站的深底观感一致。

**④ 内衬九列恢复常驻**（不再默认折叠）

`state.lwLinerDetail` 默认改回 `true`。R20.7c 折叠是因为九列 × 64px = 576px 撑爆表宽；
现在改成**按参考站的紧凑列宽重排**：

| 列 | 改前 | 改后 |
|---|---|---|
| 图标 | 44 | **52** |
| 名称 | 203 | **128** |
| 基础防弹等级 | 88 | **52** |
| 机动 | 104 | **76** |
| 四个插板列 | 40 × 4 | **32 × 4** |
| 内衬材质及总耐久 | 118 | **84** |
| 九个内衬列 | 64 × 9 | **32 × 9** |
| 防护区域 | 60 | **52** |
| 重量 | 60 | **48** |
| 获取方式 | 200 | 吃余量（`minmax(100px,1fr)`） |

固定宽合计 908px，1920 宽窗口下右栏 1404px，余量全给「获取方式」；
1504 宽窗口（右栏 1039px）下获取方式约 131px —— 21 列**一屏放得下，不再溢出**。

内衬格内容也照参考站改成**两行**（上行罗马等级、下行耐久），
表头文字在 32px 列里缩到 9px（参考站这几列的表头是部位剪影图标，本地无对应素材，用紧凑文字代替）。

**⑤ 列宽仍然只改渲染层**：`gearColumns` 与 `LW_COL_DEFAULTS` 一字未动（T24 / R11 的列定义契约），
紧凑宽度写在新的 `LW_R20_WIDTHS` 表里，由 `visibleGearColumns` 应用。
