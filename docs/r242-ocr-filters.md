# R242 · 识别净化：栏位标题黑名单 / 物品排除 / 同位去重

日期：2026-11-11 20:40–21:00 · 前置：R241（档位样式面板）

## 用户反馈（原话）

> 「位置不对啊 orc识别不出来装备的框吗 然后格又是 什么是单格 …… 识别到除了装备
> 以外的字 比如装备栏位上方的字『耳机』『头部装备』这种 还有臂带和狗牌 也不要
> 识别 小喵工具箱已经是成品可以用的程度了 你怎么会做不好呢」

## 根因（真实截图取证，53 个匹配逐条核对）

| 问题 | 证据 | 根因 |
|---|---|---|
| 位置不对 | `头部装备`/`面部装备`/`眼部装备` → 木质装备箱、`背包` → VKBO军用背包（标题在 y=1203/1276 两处都错配） | 栏位标题（印在物品格上方）被模糊层擦线错配，标签画在标题上 |
| 臂带/狗牌 | `臂带` → 臂带（白）、`狗牌` → 狗牌包 | 无物品排除机制 |
| "格"难懂 | 标签第二行「格 4.5万」 | 文案不清 |
| （附带） | `0/30` → M700 瞄具基座环；肾上腺素被『肾上』+『腺素』匹配两次；EXPIE/SDSK 老误报与正确结果同位置 | 计数形态守卫缺位（斜杠归一化后绕过）；无同位去重 |

**小喵为什么没这些问题**（MCP 复核 `PriceScanner` 方法面）：`GetCursorPos →
CursorCenteredRegion → ScanAtAsync`——它**只扫鼠标光标周围一小块**，栏位标题、
计数、其它格子根本进不了 ROI；结果写进自己工具窗的标注图，不在游戏上叠字。
我们扫用户框选的整页 → 噪音全部进入，必须靠黑名单/守卫/去重补齐。

## 修复

1. **栏位标题黑名单**（ocr.py `SECTION_HEADERS`，23 词）：耳机/头部装备/面部装备/
   身体护甲/眼部装备/眼镜/背带/臂章/臂带/主武器/副武器/近战武器/战术胸挂/口袋/
   特殊装备/背包/刀鞘/服装/弹药/弹匣/医疗/杂物/钥匙。resolve_key **整行（含去空格
   形态）在任何匹配层之前拦截**；token 层同步拦（防碎片擦线）。只拦独立成行的
   标题——『VKBO军用背包』『45+模块化背包』『NICE承重背带』等真物品全名不受影响。
2. **物品排除**（`ITEM_NAME_EXCLUDES` + `item_name_excluded`）：臂带/臂章/狗牌/
   dogtag/armband 片段，serve 级对解析出的物品名过滤（用户点名）。
3. **计数形态守卫**：`21/21`、`7/50`、`0/30`——**归一化前**查原始文本（斜杠不在
   NORM_RE 白名单，归一化后变 `0 30` 绕过守卫——首版漏网实测）；整串模糊层再加
   纯数字探针拒绝（`0 30`→`030` 这类残骸不配物品）。
4. **同位置去重**（serve `dedup_ocr_matches`，可单测）：
   - 同 id 近距 = 同一物品名的多个 OCR 片段（『肾上』+『腺素』）→ 留优；
   - 不同 id 近距 = 正确匹配与擦线误配共存（EXFIL 精确 vs EXPIE 整串模糊、
     LBCR vs SDSK）→ 按档位层级（精确4/去空格3/模糊2/整串1）+ 分数留优；
   - 远距的同 id 物品（两块夹板）各自保留；阈值随字号放大（3×h）适配任意分辨率。
5. **文案**：标签第二行「格 X」→「**单格** X」。

## 效果（用户的真实截图复验）

`53 → 38` 个匹配；用户点名的全部消失（违规残留无 ✓）；附带清掉 EXPIE/SDSK/
肾上腺素双匹配/`0/30` 等误配。剩余全部在真实物品名上（A-2607/EXFIL/CF/LBCR/
Mk17×4/OTV/Specter/STANAG×3/M856A1/M67/AFAK/AI-2/Esmarch/绷带/洛芬/止血剂/
止痛药/夹板×2/T30/针叶林-1/绳索/绒布/45+背包/NICE/洗发水…）。

## 边界

- SECTION_HEADERS 是**整词**拦截：若官方物品恰好就叫某个标题词（当前没有）会
  误拦；物品排除按名字片段（'狗牌' 片段不会误伤不含该词的物品）；
- 同位置去重阈值 3×字号高：极端紧凑布局下相邻同名物品格（中心距 <3 行高）理论
  上可能被合并——实测截图 175px 格间距 vs 90px 阈值，余量充足。
