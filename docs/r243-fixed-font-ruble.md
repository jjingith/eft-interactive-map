# R243 · 统一字号 + 精确卢布金额

日期：2026-11-11 21:08–21:25 · 前置：R242（识别净化）

## 用户反馈（原话）

> 「字体就是得固定大小 现在你搞得字体大小不同一 然后位置也不对 你是不是看不到
> 每个物体本身的方框 我要求钱是向左对齐的 而且单位不应该是万 而是卢布的单位
> 精确到个位数」

## 三项修复

### ① 字号固定统一

- R241 的 fs = 单品行框高 × 倍率——**每件物品的检测框高不同 → 字号参差**；
- R243：`label_base_font(matches)` = 所有识别行框高的**中位数**（钳 [9,300]），
  一次扫描内所有标签用同一个基准；仍是「该玩家屏幕上游戏文字的实际大小」
  （分辨率/UI 缩放自适应），只是统一成一个值；
- 档位倍率（sizeScale，默认 1.0）在此基础上仍可微调——默认配置下全场景完全一致。

### ② 精确卢布金额

- `fmt_short` 重写：`431400 → "431,400 ₽"`（千分位 + 个位精度 + ₽），万/亿简写废除；
- **字体坑**：微软雅黑/黑体/宋体都没有 U+20BD（₽）字形——PIL 无字体回退，会渲染成
  豆腐方框（取证截图实测）。解法：`_split_ruble` 拆出末尾 ₽，金额/中文用档位字体、
  ₽ 用 **Segoe UI Bold**（描边/颜色同一套 `_draw_styled`），视觉无缝；
- 实测验证：本机 4 个中文系字体全部 TOFU，Segoe UI/Arial/Consolas OK。

### ③ 左对齐

- 标签左沿 = 装备名行框左沿（ax=m.x 不变，画在名字上）——同一列物品天然对齐；
- 取证截图：三处标签左沿均为 x=40（演示帧物品名左沿）。

## 附带修复（演示暴露的真问题）

**同位置去重的垂直阈值过大**：原 3×行高同时用于水平/垂直——相邻行间距恰好也约
3×行高（演示帧 80px 行距、行高 37 → 阈值 111 > 80），**上下格的标签被误合并**
（演示 3 件只剩 2 件）。修正：水平 3h（切碎的同名片段 dx 可达 43px）、垂直
**1.2h**（相邻行 80px 安全、同片段 dy≈1 仍合并）。

## 已知边界

- **「位置」的语义**：OCR 只给文字行框，给不了格子边框（小喵同样不做方框检测）。
  当前实现把价格左沿钉在装备名左沿——若游戏内观感仍偏移，需要一张**实际浮窗叠在
  游戏上的截图**来定位是哪一段偏移（垂直偏移/DPI 换算/名字居中类武器格），
  再针对性修；
- 数值精度：单格价 = 整体/格数，四舍五入到个位（199,999.5 → 200,000）。
