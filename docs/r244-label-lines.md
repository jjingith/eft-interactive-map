# R244 价格标签三行版式：第 1 行留空、第 2 行整体价、第 3 行单格价

> 用户反馈（2026-11-11 21:24）：
> 「现在价格会和装备名称重叠 应该是再第一行是空格 第二行是单个物品的价格 第三行是耽搁（单格）价格」

## 一、问题

R241–R243 把价格标签锚在**装备名行框的左上角**，第 1 行就是整体价——直接压在装备名上。
用户要的是：**装备名自己占第 1 行（价格留空）**，价格从第 2 行开始：

```
装备名（第 1 行，价格不占用）
431,400 ₽        ← 第 2 行：整体价
单格 431,400 ₽   ← 第 3 行：单格价
```

## 二、修复

### 1. 三行版式（`tools/scan.py · render_labels`）

```python
start_y = ay + max(bh, fs) + gap          # 第 1 行 = 装备名自身，整行留空
draw(line1, (ax, start_y))                # 第 2 行：整体价
draw(line2, (ax, start_y + step))         # 第 3 行：单格价
```

- `bh` 是 OCR 量出的装备名行高——价格从**名字下沿**起笔，任何分辨率都不会压字。
- 行距 `step = max(fs + 2, 1.32 × fs)`：中文字形比 em 框向下多出约 0.3×字号（含描边/下伸部，
  实测 30px 字墨迹 33px 高），按 `fs + gap` 排两行会粘在一起；按墨迹高度算才分行清晰。
- 画布向下多留 `extra_bottom`（≈2.6×字号，不超出屏幕）：框选区贴屏幕下沿时，最后几行的价格
  仍能画在名字下方，而不是被夹回名字上。窗口仍是点击穿透的透明层，多出来的区域全透明。

### 2. 密集格子保护（真实截图暴露）

真实装备界面截图（3524×1738）验证时发现两类碰撞，都补了保护：

| 场景 | 现象 | 处理 |
|---|---|---|
| 相邻两件贴得很近（行距 < 三行块高） | 价格块压到下一件名字 | 退化为**名字右侧单行**（`主价 · 单格 …`），且右侧夹到同排邻格左沿 |
| 口袋格子只有 ~100px 宽 | 22px 的「120,000 ₽」约 112px，相邻两个价格横向粘连 | **按可用空间等比收缩**（下限 0.6×，仅在该格放不下时触发；宽格子仍是统一字号） |

同排邻格（dy≈0–3px）不再被误判为「下一行阻挡」——首版就栽在这里：洛芬与止血剂 y 只差 1px，
被当成上下关系，触发了单行退化并横向压到旁边物品名。

### 测试

新增 `tests/test_r244_label_lines.py` 5 条：

1. 装备名所在行（第 1 行）零墨迹；
2. 两行价格起点在名字下沿之后，且墨迹分成两段（有行距）；
3. `extra_bottom` 让贴屏幕下沿的标签仍画在下方；无空间时画在上方而不压名字；
4. 画布高度随 `extra_bottom` 增长；
5. 密集行距时退化为右侧单行，下一件名字保持干净。

R241 / R243 的版式断言同步更新（起点从 bbox 原点 → 名字下沿 + gap）。

## 四、边界

- 格子极窄（宽度 < 单格价文字宽度的 0.6 倍）时仍会轻微溢出——价格不可截断，这是文字宽度
  的物理下限。
- 价格按框选瞬间的位置绘制，游戏内滚动后需重新框选（与 R239 一致）。
- 「单格」= 整体价 ÷ (格宽 × 格高)，即该物品占用每个格子的均价；重量价按用户要求已移除。
