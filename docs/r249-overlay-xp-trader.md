# R249 · 浮窗按钮 XP 化 / 价格右对齐固定字号 / 禁售跳蚤改商人价

用户反馈（2026-11-12）：

> 右上角的价格切换钮和关闭键应该是两个分开的按钮，采用项目现有的 xp 风格 ui；
> 位置要微调，按钮的最下面的边应该在截图选框的最上边的上面，有一个像素间隔
> （现在按钮会挡住价格）。
> 字体有些大了，如果是单格的物资、价值高了，价格的字会超出物资的宽度。
> 现在是价格和物资右上角名称的最左侧的字向左对齐，改成最右侧的字向右对齐；
> 字体改成固定的大小，大小你自己测。
> 有些东西是不能上跳蚤的，识别出来没有价格，这种情况就按照贩卖给商人的价格显示，
> 然后标注一个红色的购物车小图标。

## 一、实测标定（字号不是拍脑袋定的）

用 `ui图标/ocr测试专用游戏内截图.png`（3840×2160 真实游戏仓库）裁出
`build/_r249_crop_stash.png`（840×500）跑本地 ONNX OCR：

| 量 | 实测 |
|---|---|
| OCR 行框高 | 19~27px，中位 **22~23px** |
| 相邻单格物品名的 x 间距（BS / BT / M856A1 …） | **126px** |
| 相邻行 y 间距 | 124~127px |
| 1×1 格宽 / 行框高 | **≈ 5.7**（1080p 同比例：11px / 63px） |

旧实现 `fs = 行框高中位数`（≈23px），`431,400 ₽` 在雅黑粗体下约 106px，
`单格 431,400 ₽` 约 114px；加上描边外扩，遇到 `4,000,000 ₽` 这类高价单格物资
就会越过 126px 格子。且旧实现是**左对齐**（价格从名字左沿向右冲进邻格）。

**本轮定值**：全场固定 `fs = 0.80 × 行框高中位数`（4K → 18px，1080p → 9px），
再按 `label_cell_unit()` 估出的 1×1 格宽做**一次全局**收缩：把四种口径、所有物品、
所有档位字体里最长的那行算出来，塞不进单格就整屏字号一起降 1px。
因此切换口径 / 不同物品看到的字号永远一致，也不会再为单件临时缩字。

`label_cell_unit()` 先按 y 把 OCR 框聚成「行」，再取行内 x 间距与行间 y 间距的
**中位数**并钳在 3.2~7 倍行高。直接对全体 x 求差会被 OCR 碎片混出 30px/66px 的
假间距（实测把格宽压到 90px、字号白缩两档），这是本轮专门修掉的坑。

## 二、改动

### 1. 两个分开的 XP Luna 按钮（`tools/scan.py`）

- `render_control()` 从「一个深色胶囊里画两段」改为**两张独立位图按钮**：
  复用项目现成的 `assets/xp-ui/btn-{normal,hover,pressed}.png`，
  按 `manifest.json` 的 `slice_1x=5` 做九宫格（`_nine_slice()`）。
  按钮从 42px 压到 24px 高时立体边框等比收成 3px，否则上下各 5px 全是
  被拉伸的深色边、中间只剩一条浅色，不像 XP 按钮。
- 两键之间留 4px **全透明间隔**，命中测试用 `hit_button()` 只放行两个矩形，
  间隔区 `HTTRANSPARENT` 直接穿透。
- 新增 `WM_MOUSEMOVE` / `TrackMouseEvent(WM_MOUSELEAVE)` 做 hover，
  `WM_LBUTTONDOWN/UP` 做 pressed，只重绘控制条（`_refresh_control()`），
  不碰价格标签位图。
- 资产缺失时 `_paint_xp_button()` 自绘 Luna 立体边框兜底（打包漏资源也不崩）。

### 2. 位置：底边贴选区顶边上方 1px

新增纯几何函数 `control_position(region, ctrl_size, screen)`：

```
cy = ry - ch - 1        # 按钮最下面一行 = ry-2，与选区顶 ry 之间空 1px
```

原来 `cy = ry + 2` 在选区内部，正好压住第一行价格。选区贴屏幕上沿时退到
选区下沿外 1px，再不行才贴屏幕上沿；绝不再落回选区里。

### 3. 右对齐 + 固定字号 + 防溢出

`render_labels()`：价格两行的**右端**都对齐 `x + w`（装备名最右侧的字），
向左展开正好落在本格内；`_fixed_label_font()` 一次算完全场字号；
`right_x()` 同时受同一行右侧最近装备名 / 区域右边界约束。

### 4. 禁售跳蚤 → 商人收购价 + 红购物车

`tools/serve.py` 新增：

- `_trader_sell_price(rec)`：取 `items.json` 的 `sl`（`[[traderId, priceRUB], …]`
  已换算卢布、降序），取最高一条。**市场页「Sell to 卖给谁」用的就是同一个
  `sl`**，口径完全一致；没有 `sl` 时退回 `p.b` 基础价并标 `traderApprox=true`。
- `_ocr_no_flea(rec)`：`ts` 含 `noFlea` 或 `src` 不含 `flea`，与市场页 `Banned` 徽章同判据。
- `POST /api/ocr/recognize`：**禁售跳蚤或快照里没有任何跳蚤报价**且能取到商人价时，
  `price.priceSource="trader"` + `price.trader`；历史窗口 `w72/w30d` 明确置空
  （商人只有一口价，不能拿跳蚤历史凑数），`price.base/perSlot` 同步换成商人价。
- `POST /api/ocr/overlay/state` 白名单加 `noFlea`（`price` 整个字典本来就会放行）。

`tools/scan.py`：`price_base()` / `is_trader_price()` —— 商人价在四种口径下显示
同一个值；`_draw_cart()` 自绘红色购物车（把手 + 梯形车斗 + 两轮，深红描边，
不用 Unicode 🛒，中文系字体没有该字形会变豆腐块），画在主价左侧，整组仍右对齐。

`js/market.js` / `market.css`：截图识别结果表里同步显示价格 + 红色「商人价」徽章。

## 四、边界

- 商人价是**一口价**：切换「最新 / 24h / 72h / 30天」都显示同一个值，这是刻意的，
  不是数据缺失。
- 允许上跳蚤但快照暂时没报价的物品也会回退到商人价并标购物车（比显示「—」有用），
  `price.noFlea` 会区分这两种情况。
- 打包时 `assets/xp-ui/btn-*.png` 必须一起带走；漏了会走自绘兜底，样式略简但可用。
