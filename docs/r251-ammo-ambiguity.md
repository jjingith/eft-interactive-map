# R251 · 同短名不同口径（.338/.300 AP、FMJ…）的区分与歧义标注

用户反馈（2026-11-12 14:20）：

> 有些子弹口径不一样但是显示的缩写名称是一样的，这该怎么区别，
> 如 .338 .300 就都有 AP 还有 fmj 之类的。

## 一、问题本质

游戏内物品名印的就是短名（AP / FMJ / BP …），**口径在截图上完全不可见**。
短名索引（`data/ocr-item-names.json`）里同名指向多件物品，实测冲突组：

| 短名 | 散装（ammo） | 弹药包（ammoBox） |
|------|-------------|------------------|
| AP   | .338 Lapua / .300 Blackout | .338（20发装）/.300（50发装）/.45 ACP（50发装） |
| FMJ  | **11 个口径**（5.45x39 / 5.56x45 / .338 / .357 / 7.62x39 / 7.62x54R / 6.8x51 / 9x39 / .50AE / .366 / 9.3x64） | 13 个 |
| BP   | 5.45x39 / 7.62x39 / 9x39 | 6 个（5.45 三种规格） |
| HP / SP / M62 / JHP / Pst … | 2~5 个口径 | 2~6 个 |

OCR 能拿到的只有「短名文本 + 右下角数量」，因此区分只能靠两类证据。

## 二、实现（`tools/serve.py`）

**① 口径正则增强**（`_AMMO_CALIBER_RE`）：原来只认 `5.45x39` 这类 ×N 形式，
`.338/.300/.45` 英制口径全部返回空串。现改为 `\d+(?:\.\d+)?x\d+|\.\d+`：
`.338 Lapua Magnum AP → .338`、`.45 ACP → .45`；`12/70` 霰弹口径仍取不到（无 x
无前导点），这类组按歧义处理。

**② 弹药包容量精确匹配**（R250 已有 `_ocr_prefer_pack`）：`xx/xx` 的数值 ↔
名字里「N发装」。
- `20/20` → `.338 AP 弹药包（20发装）` **唯一锁定**；
- `50/50` → `.300` 与 `.45 ACP` 撞车（都是 50 发装）→ 歧义。

**③ 散装口径投票收紧**（`_ocr_prefer_loose`）：票数 = 该口径在数据里包装规格
的种类数，**不是流行度**——FMJ 的 5.56 有 50/100 发两种装所以得 2 票，不代表
玩家手里的散装 FMJ 就是 5.56。因此只认压倒性证据：
- 最高口径 **≥3 种包装规格**（BP：5.45x39 三种规格 3:2:1 → 锁定；PS/US/PP 同理）；
- 或**全部包同一口径**；
- AP（.338/.300/.45 各 1）、FMJ、HP、SP、M62、JHP 分布不够压倒性 → 不锁定。

**④ 歧义标注**（`_ocr_ambiguous` / `_ocr_ambig_candidates`）：缩小后仍含
>1 个口径 → `price.ambiguous=true` + `price.candidates`（≤6 条：口径 / 名字 /
形态 / 来源 / 单价，散装按单发商人价、包按跳蚤价）。显示的价仍取自
`price.name`（每格价最高的口径），候选一并给前端核对。

**⑤ 前端**（`js/market.js` / `market.css`）：价格格追加黄色 `?` 徽章
（`.mk-ocr-ambig`），tooltip 列出全部候选价目与说明「短名相同、口径不同，
截图上无法区分」。浮窗（`scan.py`）不受影响——只读 price 数字字段。

## 三、端到端验证（合成图 `build/_r251_ambig_synth.png`）

| 格子 | 判定 | 显示 | 歧义 |
|------|------|------|------|
| AP + 20/20 | pack | .338 AP 包（20发装）商人价 450₽ | 否 |
| AP + 50/50 | pack | .45 ACP AP 包跳蚤价 39,900₽；候选：.300 商人价 450₽ | **是** |
| FMJ + 80 | loose | .338 FMJ 810₽/发 ×80 = 64,800₽；候选另列 5 个口径 | **是** |
| BP + 24 | loose | 5.45x39 BP 283₽ ×24 = 6,792₽ | 否（锁定） |

## 四、边界

- `50/50` 这类容量撞车、以及散装多口径分布均匀时，显示的价可能不是玩家手里
  那种口径的——tooltip 会明说并列出所有候选价，玩家点开看 `price.name` 核对。
  这是截图信息量的硬上限（游戏 UI 本来就不印口径）。
- 浮窗不加徽章（空间小、点击穿透层上叠 UI 会挡游戏），歧义只体现在市场页结果表。
- `12/70` vs `20/70` 霰弹（Poleva 系列）口径取不到 → 按歧义处理。
- 未改浮窗排版 / 契约 JSON / 未 commit / 未打包。

## 五、R252 追加（同日 14:50，用户确认「问号徽章有必要」）

**浮窗也画黄色 `?` 徽章**（原计划只在市场页显示）：`scan.py` 新增
`is_ambig_price()` + `_draw_ambig_badge()`——主价行最左侧画黄色圆徽章
（243,212,118 底 / 185,150,46 描边 / 深褐 ?，与市场页 `.mk-ocr-ambig` 同配色），
可与红色购物车叠加（顺序：? 徽章 → 购物车 → 价格，整行仍右对齐到名字右沿）。
`_price_line_width` / `_fixed_label_font` 把徽章宽度计入，统一字号不因徽章跳动。
无歧义的物品不画（含纯商人价）。测试 `test_r251_ammo_ambiguity.py` 的浮窗断言
迁移为「ambiguous 商人价 → 黄色像素在最左、购物车在其右；无歧义 → 无黄色」。

**大包小包确认**（用户问「同型号弹药包有大包小包区别吗」）——上一轮已实现，
本轮用合成图 `build/_r252_packsizes.png` 走线上 8787 复验：
`BS 30/30 → 30发装包`、`BS 120/120 → 120发装包`、
`M855A1 50/50 → 50发装包（145,678₽）`、`M855A1 100/100 → 100发装包（311,111₽）`，
四个规格全部按容量精确选中。

**数据源核实（用户已确认，行为正确）**：`items.json` 里 BS / BP / 部分 BT
弹药包整类标记 `noFlea` + `src=['none']`，跳蚤快照（2026-11-09 抓取）里这些条目
也没有任何报价 → 兜底显示商人价 450₽。**用户游戏内确认 BS/BP 弹药包确实不能
挂跳蚤**，数据源无误，兜底行为正确。BT 120 发装有两条 id（一条 flea 一条
noFlea），per-slot 最高选择自动采用有价的那条。
