## 0. 结论

**一句话版本**：当前逐发链路是**「一次抽样」版的 tarkovgunsmith 公式**——每发先给纸面穿透 ±1 随机，然后逐层用 `PenetrationChance` 掷一次骰子二选一（穿透：P、D 同乘 RF；挡住：只产钝伤并把钝伤继续往下一层衰减），最后把「最后一层钝伤」或「剩余伤害」交给人体。**没有任何一处按概率加权计算期望**。

**与用户模型的总体判定**：

- **头盔路径的顺序是对的**：跳弹 → 穿透 → 甲伤 → 减伤。
- **护甲路径的跳弹完全缺失**：数据里 37 块插板带 `x/y/z` 跳弹参数（其中 12 块金属插板真的有非零跳弹率），但前端只加载 `payload.helmets`、只给 `kind:"helmet"` 的层挂 `ricochet` 字段 → 插板跳弹**永远不会被读取**。
- **跳弹成立后的护甲伤害只扣 1 点耐久**，不是按甲伤公式算。
- **第二层不是「钝伤减免」步骤，而是完整地再判一次穿透**；只有当第二层自己也挡住时才会衰减钝伤，它一旦判穿就**跳过减免**。
- **甲伤用的是减伤前的 P**；同层顺序是「判穿透 → 甲伤 → 减伤」。

**盘点**：**3 处真实 bug**（数值可证：B1 / B2 / B3）、**3 处覆盖或实现缺口**（插板跳弹未接入、跳弹甲伤只扣 1、霰弹共享抖动）、**10 处代码内部自相矛盾**（B1–B10，其中 B1–B3 与上面的 bug 重叠）、**8 处有意口径差异**（逐条在 §5 点名带行号）。

### 1.2 关键点直接回答

**Q：代码里算甲伤时用的 `P` 是减伤前的还是减伤后的？**
→ **减伤前（本层入射 P）**。`var coeff = CS.armorDamageCoeff(st.pen, ...)`、`var durBase = st.pen * ...`（`combat_sim.js:459-460`），而 `st.pen` 直到 `:489-490` 才乘 `rf`。与 C# `DamageToArmor*` 用 `currentPenetration`、之后才 `currentPenetration *= reductionFactor`（`Ballistics.cs:986-994`）一致。

**Q：同一层内「甲伤」与「减伤」谁先谁后？**
→ **穿透判定 → 掷点 → 甲伤 → 减伤**。代码顺序：`chance/roll`（`:445-449`）→ 甲伤（`:453-471`）→ 分支（`:486`）→ `rf`（`:489-490`）。甲伤在分支之后按结果选系数，但计算本身发生在减伤之前。

**Q：第二层判定是「重新判穿透」还是「直接套钝伤/减伤」？**
→ **重新判穿透**。第二层走的是同一个循环、同一个 `penChanceFn`（`combat_sim.js:376-534`），它有自己真实的护甲等级（`data/items.json` 的 `aps[].cl` 为 1–5，`app.js:22267` `cls: b.cl || 0`），不是 0。
只有当它**也判为挡住**时，钝伤链才会被它自己的 `BT × bluntScale` 再衰减一次（`:521`）；如果它判穿，`bluntCarry` 原样保留、`bluntFactor = 1`（`:497-501`），**不减免**。
所以「第二层钝伤减免」在本代码里是**条件发生**，不是必然发生。

## 3. 必查项（常数 / 边界 / clamp / 双口径 / 期望）

### 3.1 防护系数 FactorA

```js
CS.armorFactorA = function (cls, durPct) {
  return (121 - 5000 / (45 + durPct * 2)) * cls * 0.1;
};                                    // combat_sim.js:33-36
```

- **耐久%的分母 = `durOrig`（出厂/纸面满耐久）**：引擎 `combat_sim.js:386` `L.dur / L.durOrig`；app `app.js:21013` 取 `durOrig`，缺失才回落 `durMax`。
- `durOrig` 来自 `data/items.json` 的 `pr.dur`（`app.js:22246-22247`），或 UI「原始满耐久」覆盖（`app.js:22227-22232`）。
- **「当前上限」不存在**：`durMax` 被写成同一个 `orig`（`app.js:22232` `return { dur: cur, durMax: orig, durOrig: orig };`；引擎默认 `combat_sim.js:143-145`），`items.json` 护甲只有 `dur` 一个耐久字段。
- **clamp**：app 侧 `Math.max(0, Math.min(100, 100*dur/orig))`（`app.js:21014`）；引擎侧不夹，但 `dur ≤ durOrig` 由 `app.js:22231` 保证，实际落在 `[0,100]`。
- **耐久 0 短路**（`combat_sim.js:399-410`）：

```js
if (L.dur <= 0) {
  entry.chance = 1; entry.penetrated = true;
  entry.penOut = st.pen; entry.dmgOut = st.dmg;
  log.layers.push(entry); continue;   // 不调 penChanceFn、不减伤
}
```
即「100% 全穿透、无减伤、P/D 原样传下一层」，与 `Ballistics.cs:783-786` 的 `if (durabilityPerc == 0) result = 1` 一致。

### 3.2 穿透判定三分支

```js
if (p <= a - 15) { return 0; }                       // app.js:20964
if (p < a) { var t = a - p - 15; return Math.max(0, Math.min(1, 0.4*t*t/100)); }
var den = 0.9 * a - p;                               // app.js:20969
if (den >= -1e-9) { den = -1e-9; }
var y = (100 + p / den) / 100;                       // app.js:20972-20973
```

| 区间 | JS | C#（`Ballistics.cs:773-797`） | 一致 |
|---|---|---|---|
| `p ≤ a−15` | `return 0` | else 分支，初值 0 | ✔ |
| `a−15 < p < a` | `if (p < a)`（前面已排除 `≤a−15`） | `factor_a-15 < p && p < factor_a` | ✔ |
| `p ≥ a` | 第三式 | `factor_a <= bulletPen`（第一支） | ✔ |

- 边界都**含**「`p = a−15` → 0」「`p = a` → 第三式（0.9）」；没有 `<` / `<=` 错位。
- `0.9a − p` 在定义域内恒为负（`0.9a < a ≤ p`），最小 `−0.1a`，**不存在除零**；JS 仍加了 `den >= -1e-9 → -1e-9`（`app.js:20970`），C# 无此保护。
- JS 比 C# 多把结果夹回 `[0,1]`（`app.js:20967`、`:20973`）。
- **缺口**：C# 有 `d == 0 → 1`（`Ballistics.cs:783-786`），`amDesmosChance` **没有**；引擎靠 `combat_sim.js:399` 兜底，但图表页直接调用它（`app.js:21262`，滑块下限 0 见 `app.js:21158`），0% 耐久时给出 98.89% 而不是 100%。

### 3.3 穿透值 ±1 浮动


### 3.5 甲伤

```js

                           : (pen / ac) * CS.ARMOR_CLASS_PROTECTION;
```

- **「防护能力」= 护甲等级 `cls`**（`ac = Math.max(1, cls)`），不是 FactorA，也不是 `ARMOR_CLASS_PROTECTION`（后者只在 video 分母用）。
- **1.2 封顶位置**：`CS.DUR_PROTECTION_CAP = 1.2`（`:27`，另在 `:69` 重复声明），只在 **video 模式**的两处 clamp 里生效；默认 `site` 模式**完全没有 1.2**。
- **区间实现**：未穿透 `[0.6, 1.1]`、穿透 `[0.5, 0.9]`（`:50-52`），与 `Ballistics.cs:811`、`:831` 逐字一致。因 `(P/AC)*10` 对真实弹药几乎恒 ≥1.1/0.9，**甲伤几乎与等级无关**（代码在 `:42` 自标风险）。

- **min 1 兜底**：`:461`，对应 `Ballistics.cs:815`、`:835`。
- **额外上限（C# 没有）**：`if (durDmg > L.dur) durDmg = L.dur;`（`:469`）。

### 3.6 钝伤与 bluntCarry 链

```js
CS.armorBluntScale = function (pen, cls, durPct) {
  return clamp(1 - 0.03 * (CS.armorFactorA(cls, durPct) - pen), 0.2, 1);
};                                    // :54-57

var bluntFactor = L.bluntThroughput * bluntScale;
if (nonPlateBacking) { bluntFactor *= CS.SOFT_LINER_PLATE_BLUNT_MUL; }   // ×0.6

                                     : (bluntCarry * bluntFactor);       // :513-529
```

- 公式 = `BT × clamp(1 − 0.03×(FactorA − P), 0.2, 1) × D`，与 `Ballistics.cs:849-868` 的 `median(0.2,…,1)` 等价。
- **层间衰减乘的是「本层的 BT × 本层的 bluntScale」**（不是固定层间系数）；只有第一层用 `D` 作为基数，后续层用 `bluntCarry`。
- **插板 ×0.6 触发**：`L.kind === 'plate'` 且 `hasNonPlateBacking(...)`（`:509`），后者要求该非插板层**同部位 + 同方向 + cls>0 + dur>0**（`:274-283`）；C# 条件只是「存在任意非插板层」（`Ballistics.cs:977`），JS 更严。
- **最终肉体伤害**：钝伤链非空 → 最后一层 `bluntOut`；否则 `st.dmg`（`:538-547`）。
- 日志矛盾：`entry.bluntBase = st.dmg * BT * bluntScale`（`:524`，不含 ×0.6）而 `entry.bluntFactor`（`:527`，含 ×0.6）。
- 上游 `aps` 缺 `bt` 时会回落到父护甲的材质与钝伤系数（`app.js:22268-22270`，代码自标 estimated）；这会直接影响层间衰减的乘数。

### 3.7 损毁系数双口径（重点）

两个**不同**的开关，别混：

### 3.8 跳弹

```js
CS.ricochetChance = function (params, angle) {
  // x = 90°概率上限，y = 最小角 z 处概率；z→90° 线性插值；angle<z 不跳弹
};
                                      // combat_sim.js:289-304
if (L.kind === 'helmet' && L.ricochet && ctx.angle > 0) { ... }
                                      // :414
```

- 语义：`x` = 90°（掠射）概率上限，`y` = 最小角 `z` 处概率，`z` = 起始角（度）；`angle < z → 0`，`angle ≥ 90 → x`，之间线性。
- **只对头盔生效**（`:414`）；插板/内衬/附加内层都没有该字段（§2.4）。
- **跳弹结果**：`entry.blunt = 0`、头盔耐久 `−min(1, dur)`、子弹终止（`:422-439`）。
- **不参与期望**：跳弹概率只是抽样分支，不做加权。
- **另有一套「跳弹」**：掩体未穿透时的 `ammo.ric × ricochetMul` 固定概率（`:342-344`），不按角度插值，且每次都会消耗一个 `rng()`。

### 3.9 期望值口径

- UI 表头：`["#","时刻","弹药","命中","部位","方向","弹丸","首层概率","首层掷点","结果","入体伤害","甲损","层后耐久","溢出"]`（`app.js:24135`）——**都是这一发的抽样值**。
- 多次运行是**蒙特卡洛统计**（击杀率、平均发数、平均耗时），种子逐次 `+1`（`app.js:22496-22516`、`24300-24308`）。
- **穿透概率与钝伤/伤害不组合**：每层掷一次，`roll < chance` 走穿透，否则走挡住；同一发里不会同时体现两者。
- C# 的期望公式 `averageDamage = penChance*penDmg + (1-penChance)*blunt`（`Ballistics.cs:984`）、多层版 `:431` **没有被移植**。
- 全仓「期望」仅 `app.js:1360` 一处（与弹道无关）。

## 6. 跳弹缺失 / 顺序错误导致的可见后果（具体数字）

### 6.1 躯干金属插板：85° 命中，跳弹被完全忽略

输入：5.45 BS（P54 / D45）× 刚玉-VM 前部（cl5 / 装甲钢 / dur60 / bt0.18 / `x0.8 y0.3 z80`）。

- **代码**：这一发按「无角度」处理 → 穿透概率 93.817%，入体 **39.01**，甲损 **15**；期望入体 **37.10**、期望甲损 **15.19**。
- **用户模型**：85° 处跳弹率 **55%**；跳弹时入体 **0**、护甲仍吃挡下甲伤 **18**；未跳弹时 39.01 / 15。
  → 期望入体 **16.69**、期望甲损 **16.73**。
- **差值**：期望入体 **+20.40**（代码是模型的 **2.22 倍**，即 +122%）；期望甲损 **−1.55**（代码少算）。
- 单发极端情形：若这一发的跳弹掷点落在 0.55 以内，用户模型该发入体 0、代码仍给 39.01 —— **单发差 39.01 点伤害**。

### 6.2 头盔跳弹成立：甲伤从 18 变成 1

输入：Maska-1SCh（cl4 / 装甲钢 / dur108 / bt0.1726 / `x0.8 y0.3 z80`）× 5.45 BS，85°（rc = 0.55）。

- **代码**：跳弹成立时 `rdmg = min(1, 108) = 1` → 耐久 108 → 107，人体 0。
- **用户模型**：跳弹成立仍按甲伤公式 → `clamp((54/4)×10)=1.1`，`54×0.57×1.1×0.525 = 17.78` → **18** 点（耐久 108 → 90）。
- **差值**：每次跳弹**少算 17 点甲损**（18 vs 1，代码是应有值的 5.6%）。连续几次掠射跳弹后，代码里的重盔几乎不掉耐久。

### 6.3 第二层顺序：钝伤减免被「穿透」绕过

输入：Granit Br5（cl6 / 陶瓷 / dur60 / bt0.28）+ 6B43 软内衬（cl3 / 芳纶 / dur85 / bt0.36），0°（§4.3）。

- **代码**：插板挡住 → 钝伤 6.1187（含 ×0.6）→ 内衬按**满 P=54** 判穿透（97.99%）→ 减免跳过 → 人体 **6.1187**。
- **用户模型**：第二层只做钝伤减免 → `6.1187 × 0.36 = 2.2027`。
- **差值**：人体伤害 **+178%**（6.1187 vs 2.2027）。并且代码这一发里内衬耐久只掉 1.55（被 `lastHardChance` 缩放），而插板掉 19。

### 6.4 顺序本身正确、数值不需要改的部分

- 头盔：跳弹 → 穿透 → 甲伤 → 减伤，顺序正确（`:411-442` → `:445-491`）。
- 穿透后：甲伤（减伤前 P）→ RF → 下一层重新判穿透，顺序正确。
- 甲的甲伤/减伤顺序与 C# 一致（甲伤先、减伤后）。
