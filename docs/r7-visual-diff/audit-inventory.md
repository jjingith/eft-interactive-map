## 三、无法对齐的原因（如实记录）

1. **视口高度不同**：原站 1920×1080 含浏览器工具栏，本地 1920×909 为纯内容视口，纵向差 171px。
2. **数据不同**：原站首屏是 Slick / 6B43 等实时商品与报价；本地为离线快照，候选条数、
   缺价标记与排序都不同，无法逐行对位。
3. **状态不同**：原站截图是「护甲」类别 + 静态列表；本地为同时展示四部位局部减益而装备了
   头盔 + 胸挂 + 护甲 + 眼镜的状态。
4. **滚动位置不同**：原站表格左端对齐、右端被窗口裁切；本地容器完整可见 1392px。
5. **没有「修复前」截图**：早期把修复后截图写进了 `baseline/` 覆盖了原帧，且该目录未被 git
   跟踪，无法从版本库恢复。因此前后对比使用**对话内已记录的修复前测量值**
   （表头/数据 11px、行高 29px、`scrollWidth === clientWidth === 2181` 无真实溢出、
   已装卡片常驻全名、内衬作为独立子卡渲染），并在报告中标注为「测得值对照，非像素叠图对照」。
