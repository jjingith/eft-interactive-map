## 五、横向滚动条（2026-10-21 第三次实测，插板四列收窄到 40px 后）

| 项目 | 实测值 |
|---|---|
| 容器 `scrollWidth / clientWidth` | **1626 / 1392**（护甲），最大 `scrollLeft` **234** |
| 滑块渲染 | 原生 `::-webkit-scrollbar` 12px；轨道 `#151515`、滑块 `#5a5a5a`（hover `#7a7a7a`）；截图中真实可见，滑块宽约 1165px |
| 滑块位置联动 | `scrollLeft` 0→234 时，滑块左端相对容器由 **15.7px → 212.7px**（3 倍放大截图像素测量），右移约 197px |
| 最右列可达 | `scrollLeft=234` 时最右「获取方式」列 `x=1733, right=1859`，容器右边界 1914，完整可见 |
| 合成输入验证 | CDP 合成的 `mouseWheel` 与 `mousePressed→mouseMoved` **对 Chromium 原生滚动条无效**（超时 / `scrollLeft` 不变）。滑块可用性因此以「真实渲染的滑块 + 位置随滚动联动」为证据，未用合成事件冒充人工拖动 |
| 无溢出类别 | `scrollWidth === clientWidth === 1392`，不显示横向滚动条 |
| 更新时机 | `setColumns()` / 切类别 / 拖列宽 / 搜索过滤后，因 `min-width:0` + `min-width:max-content` 组合，原生滚动条自动重算 |

### 8.2 未解决 / 无法核实的差异

1. **表头下的 14px 分组带（含「Armor Class 6」）未实现**。参考图 y≈32–45 有一条 `#565656`
   通栏灰带，本地没有。该带的文案与排序语义（是表头副标题、分组名还是筛选提示）在参考
   素材里无法核实，且没有对应的数据字段，因此未凭猜测实现。
2. **名称列宽度**：参考图 Icon 40 + Name 305 + 减益 125 = 470px 才到插板列；本地
   「名称 300 + 冲突 64 + 减益 104」= 468px。差 2px 是因为本地多出业务列「冲突」，
   收窄名称列换取冲突提示；不影响插板列对齐（误差 ±1px）。
3. **表头对齐**：参考图表头文字居中，本地按第七轮第 5.6 条硬性要求全部左对齐（含表头）。
   两者之一必然不同，本轮保留左对齐。
4. **插板数据条里的紫底字母徽标**：参考图恒为「H」，语义（材质缩写？等级？）无法从素材
   或数据字段核实；本地显示材质首字母（如 T / C）。徽标尺寸 9×10 vs 参考 9×9。
5. **字体族**：字号已一致（12px / 11px），但参考站为窄体（`Mov/Turn/Erg` 12 字符约 42px），
   本机系统字体更宽；在不引入外部字体的离线约束下无法复现，只对齐字号与行高。
6. **斑马纹**：参考图所有数据行一律 `#121212`（取样 18,18,18，无交替），本地偶数行
   `#181818` 仍有斑马纹。斑马纹属于全类别表格的公共样式，超出「仅修改右侧护甲表」的
   范围，本轮未改，记录待确认。
7. **正文亮度** 峰值 220 vs 参考 224–242：差一档，再提亮会与表头/次要文字失去层级。
8. **徽标字母亮度**：参考图紫底上的字母实测约 150–176（偏灰），本地为纯白 `#ffffff`；
   该差异同时受 Chromium 次像素抗锯齿彩边影响（本地文字边缘有色边，参考图为灰度抗锯齿），
   不改变字号与尺寸，未再调整。
