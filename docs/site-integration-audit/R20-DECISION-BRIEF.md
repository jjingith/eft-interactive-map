## 1. D1–D6 决策项展开（对应 reuse-vs-rebuild.md §3）

### D1 「物品」视图的导航形态
- **A. 顶栏加第 6 个一级入口**
  - 优点：入口最浅，符合 db4/eft 的"物品库是一等公民"直觉。
  - 缺点：改动现有顶栏 DOM 与 5 视图切换逻辑；任务书 7.2 要求"先检查再最小变更"，此项变更大。
  - 影响：`index.html` 顶栏 + `app.js` 视图切换 + 全部视图切换类旧测试需回归。
- **B. 「配枪」页内新增二级 Tab（物品库与枪械/配装共享同一份数据上下文）**
  - 优点：顶栏零改动；物品与枪械构建天然同域；最小变更。
  - 缺点：从地图/任务页进入物品库多一层导航。
  - 影响：仅配枪页内部结构 + 新模块自身文件。
- **C. 全局搜索命中后动态展开物品详情（不建独立页）**
  - 优点：最小实现；缺点：无法浏览分类，功能不完整。
- **建议默认：B**。理由：满足 7.2 最小变更，且 P0-1 聚合搜索可把入口补到全局层级。

### D2 价格数据是否纳入（必须带时间戳、标"历史快照"）
- **A. 纳入**：解锁 P1-2（Buy/Sell 成本）、P3-2（barter/craft 计算器）、P3-3（倒货排行）。

- **建议默认：A 的前置步骤**——先做一次"拉数可行性 + 许可确认"的验证轮（只下载样例、出报告、不进 UI），验证通过再决定落 UI。若许可不可确认，回落到 B。

## 4. 代理与网络路径说明（含本轮偏差与补测）

### 4.1 本机代理环境（实测）
- 环境变量：`http_proxy` / `https_proxy` = `http://127.0.0.1:5513`（无 `no_proxy` 设置）。
- git / npm：未配置工具级代理。
- 项目内**没有成文的代理规则文档**；事实约定来自既有构建脚本（`tools/build_gun_stats.py`、`tools/fetch_tasks.py` 等）：外网请求**显式传入代理参数**，`fetch_tasks.py` 同时支持代理与直连两种模式。

### 4.2 为什么用 `--no-proxy-server`
启动受控 Chrome 时加了 `--no-proxy-server`，原因是：Chrome 会把系统代理应用于**所有**请求，包括 `127.0.0.1`——本地静态服务（8799）与 CDP（9333）可能被路由进代理导致连不通。该参数的副作用是：对两个参考站的访问也走了直连，**绕过了系统代理**。这是本轮的执行偏差。

### 4.3 本轮实际访问路径清单
| 用途 | 路径 | 是否符合"外网走代理" |
|---|---|---|
| 初始可达性测试 | python urllib **直连**（`ProxyHandler({})`） | ❌ 偏差（绕过代理） |
| 页面取证/截图 | 受控 Chrome（`--no-proxy-server`）**直连** db4tarkov / eftarkov | ❌ 偏差（绕过代理） |
| 本地静态服务 / CDP | `127.0.0.1:8799` / `127.0.0.1:9333` 直连 | ✅（本地必须直连） |
| MCP `rea` | 仅 attach CDP 9333，自身不发起外网请求 | ✅ |
| WebFetch（早期首页探测） | 平台侧网络，不经本地代理管理 | ⚠️ 不受本地规则约束（工具行为） |

### 4.4 代理路径补测结果（本轮已补做）
经 `127.0.0.1:5513` 访问：`https://db4tarkov.com/` → **HTTP 200**（1.4s）；`https://www.eftarkov.com/` → **HTTP 200**（0.3s）。**代理路径可用**，偏差不影响结论，但后续轮次纠正为：
- 外网拉数脚本：默认走环境代理（与既有 `tools/*.py` 约定一致），并设 `NO_PROXY=127.0.0.1,localhost`。
- 浏览器类工具：改用 `--proxy-server=127.0.0.1:5513 --proxy-bypass-list=<-loopback>`，替代 `--no-proxy-server`，兼顾外网走代理与本地直连。
