# 复用 vs 新建：功能映射表与优先级（R20 第二阶段 4.2 + 第四阶段修订）

> 原则（任务书 4.2）：**能复用就不新建；新建必须是"现有模块无法承载"的功能或数据**。
> 每行给出：参考站功能 → 复用模块 → 需补足的点 → 是否新建 → 数据来源 → 优先级 → 主要风险。
> 优先级在任务书 P0–P4 基础上**按本轮审计结果修订**（有调整的会写明理由）。

## 2. 修订后的实施顺序（一次只做一个模块）

> 任务书第八阶段要求：每个模块独立走完「需求→复用确认→数据确认→最小改动→实现→测试→旧测试→浏览器验收→文档→报告」10 步。

| 批次 | 内容 | 为什么排这里 |
|---|---|---|
| **B1** | P0-3（数据血缘与校验）+ P0-4（模式读取收口） | 纯基础设施、零 UI 风险，为后续所有数据工作立规矩 |
| **B2** | P0-2（物品视图）+ P0-1（聚合搜索薄层） | 补齐最大空白（无独立物品页），且只读现有数据 |
| **B3** | P0-5（进度只读汇总）+ P1-4（收集清单） | 复用现有存储，先"看得见"再谈迁移 |
| **B4** | P3-1（价格表，带时间戳） | 解锁 P1-2 / P3-2 的前置 |
| **B5** | P1-2（Buy/Sell 成本）+ P1-1（枪械视图补强） | 依赖 B4 |
| **B6** | P2-1（任务树）+ P2-2（地图任务联动） | 纯前端 + 现有数据 |
| **B7** | P4-1（混压弹匣时序） | 复用既有模拟引擎，收益快 |
| **B8** | P1-3（弹药矩阵，**先做数据可行性验证**） | 数据不明，验证不过就降级为"不做" |
| **B9+** | P2-3（藏身处）/ P3-2（barter·craft）/ P3-3 | 需要新数据 + 新数据门禁 |

**排序理由**：先做「不引入新数据」的（B1–B3、B6、B7），再做「引入新数据」的（B4、B8、B9）——这样每个新数据模块都能复用 B1 建好的校验/门禁，避免数据污染扩散。
