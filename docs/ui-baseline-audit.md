# UI 排版基线审计（只读）

> 目的：为后续视觉调整提供一份可复算的现状基线。本文只记录测量结果，**未修改任何样式代码**。

## 0. 测量口径

| 项 | 说明 |
| --- | --- |
| 页面 | `http://127.0.0.1:8791/`（`?mini=1` 不参与本次基线） |
| 视口 | `innerWidth = 1834`，`devicePixelRatio = 0.6667`（Chrome 页面缩放 67%） |
| 方法 | 对 `#app-menubar`、`#menubar`、`#context-bar`、`#sidebar`、`#stage`、`#task-panel` 内**可见元素**逐个读取 `getComputedStyle`；四边 padding / margin、`row-gap` / `column-gap` 全量聚合；文字元素按 `font-size / line-height / font-weight / color` 分组 |
| 边框口径 | 67% 缩放下 `getComputedStyle` 把 1px 边框报成 `1.5px`、5px 报成 `4.5px`；下表边框一律折算回源码值（1px / 5px）。padding 与 gap 不受缩放影响，按实测值记录 |
| 对比度 | WCAG 2.x：sRGB → 线性 → 相对亮度 L，比值 = `(Lmax + 0.05) / (Lmin + 0.05)`。渐变底分别算暗端 / 亮端，必要时补算文字实际所在的中间带 |
| 涉及 CSS | `style.css`、`theme-windows-xp.css`、`assets/xp-ui/xp-ui.css`、`assets/xp-ui/xp-ui-app.css`、`tasks.css`、`styles/design-tokens.css`、`styles/ui-components.css` |
| 计数说明 | 下方“次数”是**可见元素实例**累计（54 行任务行会放大同一取值的出现次数），用于判断重复度，不是 CSS 声明条数 |

### 4.2 手段拆解

| 手段 | 现状 | 级差 |
| --- | --- | --- |
| 字号 | 13 → 12 → 11 → 10 | 每级 **1px**（约 −7.7% ~ −9.1%），视觉上几乎同级 |
| 字重 | 只有 400 / 700 | 二元切换；分组标题与图例小标题都是 700，无法再分层 |
| 颜色深浅 | 近灰阶梯：`#4a4a4a`、`#6a6a6a`、`#77746a`、`#7a766a`、`#8d8a7d`，外加蓝 `#204070`、`#0a3f9e`、绿 `#0b6b3a` / `#0b7a5d` | 5 个近灰之间的相对亮度差很小（例如 #7a766a 与 #8d8a7d 只差 3.72 → 2.84 的对比结果） |
| 缩进 | 仅图例子项使用 22px 左缩进（`.legend-sub`）；分组框 12px、任务栏 8/10px 只是容器内边距 | 缩进只出现在图例一处，未形成通用阶梯 |
| 边框 / 底 | 分组框 5px 位图切片、块间 1px 分隔线、任务卡 1px 边框、选中态 1px 橙边 | 用于区分“块”和“状态”，不用于区分文字层级 |

**结论**：层级目前**主要靠颜色深浅这一种手段**，字号只提供 1px 级差、字重只有 400/700 两档、缩进只在图例子项使用。近灰五色过于接近，导致“标签 / 计数 / 辅助说明”这三层在实际观感上容易糊成一层；蓝底黑字徽标则同时承担“最高层级”和“最低对比度”两个相互矛盾的角色。

---

## 5. 简短结论

1. **间距档位过多**：17 个非零取值，常规 5 档；核心只落在 `1 / 4 / 5 / 6`，其余 11 个值是长尾。`16px` 令牌已定义但未使用，左右不对称值（4/6、8/12）散落在同一行内。
2. **字号 / 行高未收敛**：同用途存在 12/13 两种字号，行高有 1.0 / 1.35 / 1.5 三套机制，另有两个派生小数值（10.5851、10.8333）；字重只有 400/700。
3. **对比度不足集中在“次要信息”**：图例名称 3.72、图例计数 2.84、上下文空槽 3.73、禁用态 2.91–2.93、蓝底徽标暗端 3.63；地名对浅底 1.04–1.24，全靠描边。主要正文、按钮、状态栏正文均通过。
4. **层级靠单一手段**：颜色是主分层手段，字号每级仅差 1px，字重二元，缩进只出现在图例子项一处；近灰五色彼此过近，三层次要信息缺少清晰阶梯。
