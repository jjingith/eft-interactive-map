## 一、项目结构（真实读取）

### 1.2 样式分层（关键发现）

`style.css` 是**深色基线**（含各模块布局与全部尺寸），`theme-windows-xp.css` 是**视觉覆盖层**。
主题文件把自己的工作分成 14 节，其中三节是"打补丁"性质的：

| 节 | 作用 |
|---|---|
| 1 | Luna 令牌（`--xp-*`，R18 建立，R19.15 扩充字体/间距/圆角/交互色） |
| 2–11 | 逐模块把深色翻成 Luna 浅色（工作台、按钮、输入、标签页、表格、滚动条、弹窗、卡片、地图周边） |
| **12** | "自动映射块（由 style.css 的深色声明**逐条**翻成 Luna 浅色）" |
| **13** | "修正层（自动映射之后的定点修色）" |
| **14** | "终层：把「渐变面」重新压回（自动块用 background 简写覆盖过…）" |

即：**同一处颜色最多要改三个地方**（基线 → 自动映射 → 修正/终层）。这是本轮设计系统要解决的头号结构问题。
新模块（弹药、任务）又各自追加了 `am-*`、`tk-*` 令牌与硬编码色，形成第 4、5 套近似值。

## 四、逐项审计

### 4.1 页面布局

| 项目 | 现状 |
|---|---|
| 导航 | `.menubar` 固定高 34px（`style.css:90`），5 视图按钮 + 3 下拉；任务模块自己又在内部做了一套 `.tk-tab` 标签 |
| 顶部工具栏 | 地图：无；配装 `.lw-top`；配枪 `.gw-top`；弹药 `.am-top`；任务 `.tk-head`（三层：标题栏/标签行/筛选行）。**五套工具条高度与内边距各不相同** |
| 侧栏 | 地图 `.sidebar`；配装 `.lw-side`；弹药筛选 `.am-filters`；任务无侧栏（用右侧 `.tk-side` 摘要） |
| 主体 | 地图画布 / 表格 / SVG 任务树 / 散点图，各自滚动与尺寸策略 |
| 弹窗 | 3 套（见 3.1），遮罩透明度、圆角、关闭按钮尺寸不同 |

### 4.2 颜色体系

- 已有语义令牌（`--xp-*`）：面/边/文本/选中/状态/悬停，共 ~50 个，**命名清晰**（如 `--xp-sel`、`--xp-border-dark`）。
- 但落地率只有 37.9%（颜色声明维度）。`style.css` 里 302 种颜色中大量是原始深色主题遗留，
  现在被主题层覆盖后**实际不可见**，却仍在参与层叠计算（改色时容易改错一层）。
- 状态色三套并存：`--xp-ok/warn/bad`（主题）、`--lw-positive/warn/bad`（配装）、`--am-ok/warn/bad`（弹药）。

### 4.3 字体体系

`--xp-font-family` 已定义（Tahoma + 微软雅黑），但仍有模块直接写 `font: 12px/1.5 var(--xp-font)` 或
`font: 11px Tahoma`。字号 30 种，其中 `10.5/11.5/12.5/13.5px` 这类半像素值在 Windows 上会被取整，
不同缩放比下列宽会跳。

### 4.4 间距体系

`--xp-space-1..7`（4/6/8/12/16/20/24）存在，但 `padding` 取值：`style.css` **111 种**、`tasks.css` 30 种、`calibrator.css` 14 种（含 `3px 6px`、
`2px 4px 2px 6px` 等组合），组件之间难以对齐。

### 4.5 控件体系

- 按钮：无统一 `.btn`；`.menu-btn`（菜单栏）、`.tk-btn`（任务）、`.lw-*`（配装）、`.cal-*`（校准器）各自实现凸起/悬停/按下。
- 输入框：白色内凹边框写法重复 5 次以上；聚焦态有的用 `outline: 1px solid --xp-sel`，有的改 `border-color`。
- 复选框/单选框：`tasks.css` 12 处、`app.js` 11 处，均为原生控件 + 局部 `accent-color`，**无统一尺寸**。
- 表格：列宽用 `grid-template-columns` 写死在各模块（任务表 9 列、弹药表、配装表各一套），无公共表格组件。
- 标签/徽标：`.tk-badge`、`.lw-*tag`、`.am-*chip`，圆角与内边距不一致。

### 4.6 交互状态

| 状态 | 现状 |
|---|---|
| Hover | 按钮 hover 用琥珀渐变（`--xp-btn-hover-*`），表格行 hover 用浅蓝（`--xp-row-hover`）——**两套"悬停语言"** |
| Selected | 表格行选中蓝底（`--xp-row-sel`），任务树节点选中橙边（`#e8a33d`），模式按钮选中琥珀底（`#ffeec6→#ffd98a`）——**三种"选中语言"** |
| Pressed | 只有部分按钮有 `:active`（主题第 4 节），任务模块的 `.tk-btn` 完全没有按下态 |
| Focus | 只有输入框有 `outline`，按钮与标签页靠浏览器默认焦点环；键盘 Tab 到任务树 SVG 节点时**无可见焦点** |
| Disabled | 有 `--xp-btn-disabled-*` 令牌，但任务模块的禁用按钮只有 `opacity`，没有 `pointer-events: none`/`aria-disabled`，仍可点击 |
| Error | 无统一错误态；任务模块用 `.tk-alert.is-warn` 提示，配装用 `.lw-bad` 文字色 |
| Loading | 无统一 loading；任务模块用状态栏文字「正在加载…」，配装用占位符 |
| Conflict | 配装的"槽位冲突/未装配"用红字 + 图标，未抽象为可复用状态 |

### 4.7 样式风险

1. **三层覆盖**（基线 → 自动映射 → 修正/终层）：改一个面色的成本是 3 处。
2. **作用域靠前缀**：`html .loadout-workbench .lw-top` 之类的高特异性选择器，新控件很难"自然继承"。
3. **深色残留**：`style.css` 中 302 种颜色里大部分是已不可见的旧深色值，误导后续维护者。
4. **内联样式 61 处**：`el.style.width = …` 绕过设计系统（多为列宽/进度条，属合理例外，但未集中管理）。
5. **`!important` 5 处**：数量少，但其中 3 处在主题层用于压过基线，说明层叠方向仍未理清。
6. **重复 id/类名语义**：`.tk-side`（任务右栏）与 `.lw-side`（配装左栏）都叫 side，含义相反。

### 4.8 XP 风格现状

已具备（R18/R19.15 的成果，**要保留**）：

- Luna 蓝标题栏渐变 `--xp-luna-1/2/3`；米灰工作面 `--xp-face`；白面 `--xp-face-3`。
- 凸起按钮（上亮下暗双边框）、内凹输入框（`#7f9db9` 边）、XP 列表视图表头（白→米灰渐变 + 交替行 + 蓝底选中）。
- 状态色浅底可读版；滚动条浅色滑块（限工作台与侧栏，不动地图画布）。

缺失或不一致：

- 没有"分组框（GroupBox）"标准：现有 `fieldset`/`details`/`div+标题` 三种。
- 没有统一标题栏组件：弹窗各自画标题栏，任务模块的模式说明条又是另一种"信息条"。
- 图标尺寸不一（12/14/16/18px 混用），且任务树用字符符号（○◐✓✕）而非图标。
- 地图画布与小字号区域（9/10px）虽属合理例外，但没有在规范里写明"例外范围"，容易被后来者当作"可以继续用 9px"。

## 七、结论：设计系统必须解决的 5 件事

1. **单一颜色入口**：新代码只认语义令牌；旧的三层覆盖不再扩大，按模块逐步收敛（见 `design-spec.md` 的迁移策略）。
2. **一组基础组件**：按钮 / 输入 / 下拉 / 复选 / 标签页 / 面板 / 表格 / 徽标 / 工具条 / 弹窗 / 菜单 / 提示，
   每类只有一个实现，带完整状态。
3. **明确的状态语义**：蓝=选中/焦点，琥珀=悬停/分段当前项，红=危险，绿=成功；按下有下沉位移，禁用需 `disabled`+`aria-disabled`。
4. **层级令牌**：dropdown / overlay / dialog / menu / tooltip / toast 各有固定层级，禁止再用魔术数字。
5. **可验证**：设计系统自带展示页 + 自动化检查（令牌是否加载、组件结构是否正确、离线是否无外链），
   让后续 Agent 的改动能被机器拦住。
